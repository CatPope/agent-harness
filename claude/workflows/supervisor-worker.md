## Supervisor–Worker — Claude 감독 · Codex 구현

이 프로젝트는 **Claude 가 명세·역할배분·검수를 맡고 Codex 가 정밀 구현을 맡는**
Human-in-the-loop 구성으로 일한다. 주요 의사결정은 사용자가 승인한다.

### 코드 구현은 Codex 에 위임한다

관리자(Claude)는 무엇을 만들지 정하고, 넘기고, 돌아온 것을 검수한다.
**관리자가 코드를 직접 붙들고 있는 쪽이 더 자주 사고가 난다.**

### 누가 할지는 한 줄로 가른다

> **결과물이 프로젝트의 구현 코드 자산인가.**

그렇다면 Codex. 아니라면 관리자. 애매하면 **위임한다.**

| 관리자(Claude)가 직접 | Codex 에게 위임 |
|---|---|
| 아키텍처·설계, 계획 수립 | 정밀 코드 생성, 모듈 구현 |
| 작업지시서 작성 | 학습·평가 스크립트, 파이프라인 |
| 맥락 종합·조율·우선순위 | 뼈대가 잡힌 뒤의 반복 확장 |
| 결과 검수 | 대규모 실행·벤치마크 |
| 전략 문서·진행상황 | 코드 레벨 문서(README·주석) |

문서 변환용 소규모 스크립트나 분석을 위한 즉석 조회는 예외다 — 프로젝트에 남는 자산이 아니다.

가르기 전에 **미정인 결정이 남아 있지 않은지** 확인한다. 미정 상태로 넘기면 실행자가
대신 정해 버린다. 되돌릴 수 없는 일(삭제·배포·외부 전송)은 넘기지 않는다.
→ [[role-split]]

### 위임 메커니즘은 codex-delegate 다

같은 Codex 세션을 유지하고(`thread_id`), 자유 서술이 아니라 **구조화 완료보고(JSON)** 를
받는다 — 참고한 소스 · 수정 파일 · 실행 명령 · 테스트 실행 여부 · 미완 항목.
`unfinished` 가 비어 있지 않으면 그게 진짜 상태이고, `blocked: true` 면 검수를 건너뛰고
사용자에게 직행한다. 실행 중에는 이벤트 로그를 주기적으로 확인해 방황·차단을 일찍 잡는다.
→ [[codex-delegate]] · 실행자가 남기는 보고 형식은 [[codex-completion-report]]

### 검수가 "재설계"로 나오면 배분부터 다시 한다

결과물이 아니라 **역할 배분이 틀렸다**는 뜻이다. 같은 배분으로 다시 넘기지 않는다.

> 같은 워크플로우를 `openai/codex-plugin-cc` 로 도는 대안 메커니즘 [[codex-plugin-flow]] 도
> 함께 설치된다. **기본은 `codex-delegate`** 이고, 어느 쪽을 쓰는지는 프로젝트 지침의
> 스위치가 정한다. 플러그인 쪽은 시범 보류 상태이며, 그 스킬 맨 앞의 재개 체크리스트
> 4항목을 통과하기 전에는 켜지 않는다.
