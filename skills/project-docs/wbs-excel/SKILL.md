# WBS 엑셀 일정표

## 무엇을 만드는가

`[1차] WBS_일정관리_vX.Y.Z.xlsm` 과 같은 버전의 `.html`. 생성기는 실행 폴더의 `out/` 에 쓴다(`OUT_DIR` 로 바꾼다).
양식은 `templates/[양식] WBS_일정관리.xlsx` 다. 양식 파일은 읽기만 한다.

🔴 **양식 고르는 순서.** 사용자가 따로 준 양식이 있으면 그것을 쓴다. `templates/` 의 양식은 사용자 양식이 없을 때만 쓴다.
먼저 사용자에게 받은 양식이 있는지 확인하고, 있으면 생성기에 환경 변수 `TEMPLATE` 로 그 경로를 준다.
생성기는 양식의 구조(본보기 문단·표·도형 번호)를 전제한다. 다른 양식이면 구조를 먼저 덤프하고 생성기를 맞춘다.

`examples/` 에 한 프로젝트(9주, 네 명)의 v2.5.0 을 가명으로 만든 결과가 있다. 생성기의 `SECTIONS` 도 그 내용이다.
사용자가 엑셀에서 바꾼 구분 행 평균 수식 두 칸만 원본과 다르다(함정 절의 `AVERAGE` 항목).

시트 다섯 장이 있다.

| 시트 | 역할 |
|---|---|
| `일정 관리` | 원본. 번호 · 작업 제목 · 담당자 · 완료 비율 · 우선순위(S/C) · 시작주 · 끝주 · 주 단위 막대 |
| `인원별` | 사람별로 다시 묶은 보기. VBA 가 관리한다 |
| `용어 사전` | 용어 설명 |
| `설정` (숨김) | 인원 이름 · 역할 · 비고. 비고가 있으면 미참여로 본다 |
| `_서식` (숨김) | VBA 가 복사해 쓰는 행 서식 3줄 (구분 · 항목 · 합계) |

막대는 색칠이 아니다. 우선순위 · 시작주 · 끝주 값과 조건부 서식으로 그려진다.
값을 고치면 막대가 따라온다. 1행에 흰 글씨로 주 번호가 숨어 있고 조건부 서식이 그것을 본다.

작업 제목 칸은 **모든 행에서 C:G 병합** 이다 (v2.3.0, 2026-09-24 사용자 지시). 구분 · 항목 · 하위 항목 · 합계 행이
다 같다. 하위 항목은 D 열이 아니라 C 에 넣고 앞에 빈칸 네 개로 들여쓴다 (`SUB_INDENT`). 열 너비는 시트마다 다르다 —
`일정 관리` 는 F·G 를 좁혀(2.4 · 3.1) 타임라인이 한 화면에 들어오게 하고, `인원별` 은 양식 너비 그대로 둔다.

## 언제 어떤 방법으로 고치는가

| 상황 | 방법 |
|---|---|
| 완료 비율 · 주차 · 담당자 · 제목 몇 개를 고친다 | 사용자가 엑셀에서 직접 고친다. 스크립트를 돌리지 않는다 |
| 작업을 추가한다 | `일정 관리` 에 행을 넣고 번호(`4.8` 처럼 점 포함) · 담당자 · S/C · 시작주 · 끝주를 채운다 |
| 사람을 더하거나 뺀다 | 숨김 시트 `설정` 을 고친다. `인원별` 탭을 다시 열면 반영된다 |
| 기간 · 주 수 · 영역 구조가 바뀐다 | `scripts/wbs_build.py` 의 상수와 `SECTIONS` 를 고치고 다시 만든다 (X 올림) |
| HTML 만 다시 만든다 | 같은 스크립트를 돌린다. HTML 은 스크립트의 `SECTIONS` 에서 나온다 |

🔴 엑셀에서 사용자가 고친 뒤에는 스크립트의 `SECTIONS` 가 낡는다. 스크립트를 다시 돌리기 전에
현재 xlsm 의 값을 `SECTIONS` 에 옮겨 적는다. 그렇지 않으면 사용자의 수정이 사라진다.

## 사용자가 고친 파일에 VBA 만 갈아끼우기

사용자가 값·행·서식을 직접 고친 xlsm 이 있고 고칠 것이 VBA 뿐이면 **다시 만들지 않는다.**
`update_vba.ps1` 이 그 파일의 `WbsSync` 와 인원별 시트 모듈을 `scripts/` 의 `.bas` 로 바꿔 새 이름으로 저장한다.

```powershell
<스킬>\scripts\update_vba.ps1 -In "<폴더>\레거시\[1차] WBS_일정관리_v<이전>.xlsm" -Out "<폴더>\[1차] WBS_일정관리_v<새>.xlsm"
```

그 뒤 `SECTIONS` 를 사용자 값으로 옮겨 적고 `wbs_build.py` 를 돌려 같은 버전의 HTML 만 쓴다(xlsm 은 덮지 않는다).
옮겨 적은 것이 맞는지는 `%TEMP%\wbs_v<새>_nomacro.xlsx` 와 사용자 파일의 A·C·H·I·J·K·L 열을 openpyxl 로 비교한다.
차이가 수식 몇 개뿐이어야 한다. 2026-09-24 v2.4.0 이 이 절차로 나왔다.

## 준비 (처음 한 번)

```powershell
<스킬>\setup.ps1   # openpyxl 설치, Excel 의 AccessVBOM 확인
```

파이썬 3.10 이상과 데스크톱 Excel 이 있어야 한다. LibreOffice 는 쓰지 않는다.
양식은 스크립트 위치 기준 `../templates/` 에서, 결과는 실행 폴더 기준 `out/` 에서 잡는다. 결과를 둘 폴더에서 실행한다.

## 다시 만드는 절차

1. 버전을 정한다. X 기간·범위·구조 / Y 항목·배분·시트 기능 / Z 색·서식·오탈자.
2. `scripts/wbs_build.py` 맨 위의 `VER` 과 `SECTIONS` 를 고친다.
3. 현재 파일을 같은 폴더의 `레거시/` 로 옮긴다. xlsm 과 html 둘 다.
4. 만든다.

```powershell
python <스킬>\scripts\wbs_build.py        # %TEMP%\wbs_v<VER>_nomacro.xlsx + out 의 .html
<스킬>\scripts\inject_vba.ps1 -Ver <VER>  # VBA 를 붙여 out 에 .xlsm 저장 (-OutDir 로 바꾼다)
```

5. 검증한다. LibreOffice 가 없으므로 Excel COM 으로 한다.

```powershell
$xl = New-Object -ComObject Excel.Application; $xl.Visible=$false; $xl.DisplayAlerts=$false
$wb = $xl.Workbooks.Open("<xlsm 경로>"); $xl.CalculateFull()
# 모든 시트에서 '#' 로 시작하는 셀이 없어야 한다
# 인원별 시트를 Activate 해서 RebuildPeople 이 도는지, 값을 바꿔 원본에 써지는지 본다
# ExportAsFixedFormat(0, "<pdf>") 로 뽑아 Read 도구로 막대 색과 열 너비를 눈으로 본다
$wb.Close($false); $xl.Quit()
```

6. 프로젝트 안내 문서의 일정표 경로와 진행 기록의 상태 표를 갱신한다.

## VBA 동기화가 하는 일

`scripts/WbsSync.bas` (표준 모듈) 과 `scripts/SheetPeople.bas` (인원별 시트 모듈).

- `인원별` 시트를 열면 `RebuildPeople` 이 원본을 읽어 사람별 블록을 다시 만든다.
  잎 행(완료 비율이 수식이 아닌 작업 행)만 담고, 시작주 · 끝주 · 번호 순으로 늘어놓는다.
  `전원` 담당 작업은 비고가 없는 사람에게만 붙는다.
- `인원별` 에서 값을 고치면 `PushToSource` 가 번호로 원본 행을 찾아 써 넣고, 셀을 참조 수식으로 되돌린다.
  제목은 하위 항목도 C 열에 쓴다 (앞 빈칸 포함).
- 다시 만든 행마다 `MergeTitle` 이 C:G 를 병합한다. `_서식` 행의 서식 복사가 병합을 같이 옮기지만 보장용이다.
- **속도 규칙 (v2.4.0, 실측 13~23초 → 0.4초)**: 재조립 동안 `Calculation = xlCalculationManual`. 서식은 행마다 붙여넣지 않고
  `_서식` 행을 사람별 블록으로 한 번에 `Copy Destination:=` 한다. 수식은 열마다 배열로 한 번에 넣는다. 원본 셀은 한 번만 읽어
  배열에 캐시한다. 끝에 `ResetBars` 가 조건부 서식을 지우고 전체 범위에 두 개만 다시 건다 — 행마다 붙여넣으면 규칙이
  84개까지 불어나 계산이 느려진다. VBA 의 `COLOR_S`/`COLOR_C` 는 파이썬 `GREEN`/`YELLOW` 와 같아야 한다.
- `전원` 작업은 VBA 가 비고 없는 사람 모두에게 붙인다. 파이썬 `SECTIONS` 도 같은 사람들을 적어야 HTML 과 첫 조립이 어긋나지 않는다.
- 인원별 셀의 참조 수식은 파이썬의 `ref_formulas` 와 VBA 의 `FormulaFor` 가 같아야 한다. 한쪽을 고치면 다른 쪽도 고친다.

파일을 열 때 "콘텐츠 사용" 을 눌러야 동작한다. 안 누르면 인원별은 수식만 살아 있는 읽기 전용이 된다.

## 함정 (실측)

- Excel COM `SaveAs` 는 파일 이름에 `[` `]` 가 있으면 거부한다. 임시 이름으로 저장한 뒤 `Move-Item` 으로 옮긴다.
  `Workbooks.Open` 은 괜찮다.
- VBA 를 COM 으로 넣으려면 `HKCU\Software\Microsoft\Office\16.0\Excel\Security\AccessVBOM = 1` 이어야 한다.
  보안 설정이므로 켜기 전에 사용자에게 먼저 묻는다.
- 조건부 서식 셀에 `0%` 숫자 서식이 딸려 오면 시작주가 `400%` 로 보인다. 우선순위 · 시작주 · 끝주 열은 `General` 로 둔다.
- 양식의 구분 행은 담당자 칸(H)만 회색이 빠져 있다. 스크립트가 채운다.
- 완료 비율(I) 열은 양식 너비 4.63 이면 **구분 행(11pt 굵게)의 100% 가 `####`** 이 된다. 항목 행(10pt)만 보고 넘어가기 쉽다.
  Excel 5.5 부터 보이므로 생성기가 6.0(openpyxl 6.7)으로 둔다. 검증할 때는 잎 행을 전부 100% 로 채우고 `.Text` 에 `#` 이 없는지 본다.
- openpyxl 이 만든 파일은 수식이 계산돼 있지 않다. 반드시 Excel 로 열어 `CalculateFull` 뒤에 본다.
- `| tail` 뒤에서는 종료 코드가 가려진다. 검증 스크립트의 결과는 파일로 남기고 종료 코드는 따로 본다.
- 실행 결과 콘솔에 `?` 가 찍히는 것은 cp949 콘솔이 `—` 를 못 그리는 것이다. 파일은 멀쩡하다.
- HTML 은 정적이다. 엑셀을 고쳐도 HTML 은 안 바뀐다. 사용자에게 그렇게 말한다.
- 사용자가 `일정 관리` 에 행을 끼워 넣으면 **구분 행의 `AVERAGE(I14,I15,…)` 가 새 행을 빠뜨린다** (v2.3.1 에서 2.6 이 빠졌다).
  사용자 파일을 받으면 구분 행 수식이 그 구분의 잎 행을 다 품는지 본다. `AVERAGE(I14:I22)` 처럼 범위로 고쳐 둔다.
- 담당자가 세 명이어도 전원이 아니면 이름을 다 적는다. `전원` 은 인원 전부일 때만 (생성기 `len(who) >= len(PEOPLE)`).
- 검증 스크립트는 `AutomationSecurity = 1` 로 열어야 `Worksheet_Activate` 가 돈다. `3` 이면 매크로 없이 열려 재조립을 못 본다.

## 관계

- 범용 xlsx 조작 · 수식 규칙은 따로 설치한 xlsx 스킬이 있으면 그것을 따른다.
- 문서 버전 · 레거시 규칙은 프로젝트 지침을 따른다. 없으면 위 다시 만드는 절차의 1번을 쓴다.
- 검증 수단 고르기는 [[verification-route]], 결과 대조는 [[work-review]].

## 사용자가 엑셀에서 고친 서식은 생성기에 되먹인다

사용자가 xlsm 을 직접 고치면, 다음 판을 만들기 전에 **내 생성본과 사용자 파일을 셀 단위로 비교**한다.
값·글꼴·채움·정렬·테두리를 openpyxl 로 비교하고, 열 너비·배율·틀 고정은 **Excel COM 으로** 읽는다.
openpyxl 은 Excel 이 묶어 저장한 열 범위(`<col min max>`)의 두 번째 열부터 기본값 13 을 돌려주므로
열 너비 비교에 쓰면 안 된다(실측: N~BE 가 전부 13 으로 보였다).

🔴 **시트마다 따로 비교한다.** v2.2.0 에서 `일정 관리` 의 F·G 축소를 `인원별` 에도 적용했는데, 사용자는
`인원별` 은 손대지 않았었다. 사용자가 "v2.1.0 으로 돌려 달라" 고 해서 v2.3.0 에서 시트별로 되돌렸다.
한 시트에서 본 변경을 다른 시트에 옮기지 않는다.

지금까지 되먹인 것 (2026-09-24):
- v2.1.0 → v2.2.0: `일정 관리` 제목 칸 F·G 열을 2.4·3.1 로 줄임 — 타임라인이 한 화면에 들어오게. 두 시트 배율 70%.
  담당자 변경(4.5·4.6 → 박민수)은 `SECTIONS` 에 옮겨 적음
- v2.2.0 → v2.3.0: `인원별` F·G 는 양식 너비로 복원. 작업 제목 C:G 를 전 행 병합, 하위 항목은 앞 빈칸(사용자 지시)
- v2.3.1 → v2.4.0: `일정 관리` H(담당자) 를 19 로 넓힘(사용자 18.38, 세 명 이름). 배분 7건은 `SECTIONS` 에
