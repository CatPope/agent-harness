# UI 디자인 원칙

## 왜 있는가

2026-09-26 에 디자이너에게 보여 줄 클릭 데모를 만들었다. 사용자는 "모던함을 중점으로 두되 꼼꼼한 디자인은 중요하지 않다.
기능이 모두 들어가야 한다" 고 했고, Figma 의 UI 디자인 원칙 글을 참고하라고 했다.
출처는 Figma 리소스 라이브러리 「UI 디자인 원칙」(https://www.figma.com/ko-kr/resource-library/ui-design-principles/, 2026-09-26 확인)이다.

## 원칙 7가지와 적용 예

| 원칙 | Figma 의 설명 | 적용 예 (모임 관리 앱) |
|---|---|---|
| 계층 구조 | 크기, 굵기, 색 대비, 간격으로 먼저 볼 것을 정한다. 무엇을 먼저 보고 무엇을 스크롤해야 보는지 의도한다 | 화면마다 가장 중요한 것 하나를 위에 크게 둔다. 홈은 다음 발표 일정, 일정 탭은 지금 해야 할 일 |
| 점진적 공개 | 여러 단계로 나눠 단계마다 필요한 정보만 준다. 현재 단계와 남은 단계를 보여 준다 | 가능 시간 입력을 두 단계로 나눈다(날 고르기, 시간 정하기). 단계 표시 1/2, 2/2 |
| 일관성 | 버튼 모양, 패턴, 동작을 제품 전체에서 같게 둔다. 벗어날 때는 근거가 있어야 한다 | 주 버튼은 한 가지 모양. 하단 탭 5개는 모든 화면에서 같은 자리. 팝업은 공통 가이드의 유형만 쓴다 |
| 대비 | 중요한 기능에 색 대비로 눈을 끈다. 위험한 동작은 빨강, 보조 동작은 회색 | 강조색은 주 동작에만. 일정 변경, 삭제 같은 되돌리기 어려운 동작은 빨간 글자 버튼 |
| 접근성 | 대체 텍스트, 충분한 여백, 보조 기술 호환, 키보드 탐색, 전경·배경 대비(WCAG) | 본문 대비 4.5:1 이상. 누르는 영역 44px 이상. 버튼은 `<button>`, 아이콘만 있는 버튼에는 `aria-label` |
| 근접성 | 관련 있는 요소를 붙여 둔다. 실수하면 안 되는 버튼은 떨어뜨린다 | 임시 저장하기와 발송하기는 붙이되, 발송하기만 강조색. 로그아웃은 목록 맨 아래에 따로 |
| 정렬 | 그리드로 질서와 균형을 만든다. 가독성과 예측 가능성이 오른다 | 4px 배수 간격. 왼쪽 정렬을 기본으로, 숫자는 오른쪽 정렬과 고정폭 숫자 |

## 모던하게 보이는 최소 규칙

꼼꼼한 디자인이 필요 없을 때도 이것만 지키면 정돈돼 보인다.

- 색은 토큰으로 정한다. 배경, 면, 선, 글, 흐린 글, 강조색 하나, 위험색 하나, 성공색 하나. 강조색을 여러 개 쓰지 않는다.
- 회색은 강조색 쪽으로 살짝 기운 회색을 쓴다. 순회색은 고르지 않은 것처럼 보인다.
- 간격 척도는 4, 8, 12, 16, 24, 32 만 쓴다. 요소 사이는 `gap` 으로 준다.
- 모서리는 두 가지만. 카드와 팝업 16px, 버튼과 입력칸 10~12px.
- 그림자는 떠 있는 것(팝업, 하단 시트, 토스트)에만 준다. 모든 카드에 그림자를 주면 계층이 사라진다.
- 글꼴은 하나(한글은 Pretendard, 없으면 맑은 고딕). 크기 척도는 12, 13, 15, 17, 20, 24 정도.
- 상태를 색만으로 나타내지 않는다. 뱃지에 글자를 함께 쓴다(발송, 실패, 임시저장).
- 이모지와 그라데이션은 쓰지 않는다. 아이콘은 선 아이콘 한 벌만.
- 다크 모드는 토큰을 한 번 더 정의하는 것으로 끝낸다. 데모에서 필수는 아니다.

## 데모 화면의 상태

화면은 비어 있는 모습으로 열지 않는다. 예시 데이터를 채워 무엇을 하는 화면인지 바로 보이게 한다. 예시라는 표시는 한 곳에 둔다.
각 목록 화면은 세 상태를 생각해 둔다. 데이터가 있을 때, 없을 때, 불러오는 중이거나 실패했을 때.

## 점검표

- [ ] 화면마다 가장 먼저 볼 것이 하나인가
- [ ] 주 버튼이 한 화면에 하나인가
- [ ] 같은 동작이 모든 화면에서 같은 모양과 자리인가
- [ ] 위험한 동작에 확인 단계가 있는가
- [ ] 여러 단계 입력에 현재 단계가 보이는가
- [ ] 휴대폰 폭(360~400px)에서 가로 스크롤이 없는가
- [ ] 글과 배경의 대비가 충분한가
- [ ] 상태가 색과 글자로 함께 보이는가
