# UI 디자인 원칙

## 왜 있는가

2026-09-26 에 디자이너에게 보여 줄 클릭 데모를 만들었다. 사용자는 "모던함을 중점으로 두되 꼼꼼한 디자인은 중요하지 않다.
기능이 모두 들어가야 한다" 고 했고, Figma 의 UI 디자인 원칙 글을 참고하라고 했다.
출처는 Figma 리소스 라이브러리 「UI 디자인 원칙」(https://www.figma.com/ko-kr/resource-library/ui-design-principles/, 2026-09-26 확인)이다.

## 원칙 7가지와 적용 예

| 원칙 | Figma 의 설명 | 적용 예 (모임 관리 앱) |
|---|---|---|
| 계층 구조 | 크기, 굵기, 색 대비, 간격으로 먼저 볼 것을 정한다. 무엇을 먼저 보고 무엇을 스크롤해야 보는지 의도한다 | 화면마다 가장 중요한 것 하나를 위에 크게 둔다. 홈은 다음 발표 일정, 일정 탭은 지금 해야 할 일 |
| 점진적 공개 | 여러 단계로 나눠 단계마다 필요한 정보만 준다. 현재 단계와 남은 단계를 보여 준다 | 가능 시간 입력을 두 단계로 나눈다(날 고르기, 시간 정하기). 단계 표시 1/2, 2/2 |
| 일관성 | 버튼 모양, 패턴, 동작을 제품 전체에서 같게 둔다. 벗어날 때는 근거가 있어야 한다 | 주 버튼은 한 가지 모양. 하단 탭 5개는 모든 화면에서 같은 자리. 팝업은 공통 가이드의 유형만 쓴다 |
| 대비 | 중요한 기능에 색 대비로 눈을 끈다. 위험한 동작은 빨강, 보조 동작은 회색 | 강조색은 주 동작에만. 일정 변경, 삭제 같은 되돌리기 어려운 동작은 빨간 글자 버튼 |
| 접근성 | 대체 텍스트, 충분한 여백, 보조 기술 호환, 키보드 탐색, 전경·배경 대비(WCAG) | 본문 대비 4.5:1 이상. 누르는 영역 44px 이상. 버튼은 `<button>`, 아이콘만 있는 버튼에는 `aria-label` |
| 근접성 | 관련 있는 요소를 붙여 둔다. 실수하면 안 되는 버튼은 떨어뜨린다 | 임시 저장하기와 발송하기는 붙이되, 발송하기만 강조색. 로그아웃은 목록 맨 아래에 따로 |
| 정렬 | 그리드로 질서와 균형을 만든다. 가독성과 예측 가능성이 오른다 | 4px 배수 간격. 왼쪽 정렬을 기본으로, 숫자는 오른쪽 정렬과 고정폭 숫자 |

## 모던하게 보이는 최소 규칙

꼼꼼한 디자인이 필요 없을 때도 이것만 지키면 정돈돼 보인다.

- 색은 토큰으로 정한다. 배경, 면, 선, 글, 흐린 글, 강조색 하나, 위험색 하나, 성공색 하나. 강조색을 여러 개 쓰지 않는다.
- 회색은 강조색 쪽으로 살짝 기운 회색을 쓴다. 순회색은 고르지 않은 것처럼 보인다.
- 간격 척도는 4, 8, 12, 16, 24, 32 만 쓴다. 요소 사이는 `gap` 으로 준다.
- 모서리는 두 가지만. 카드와 팝업 16px, 버튼과 입력칸 10~12px.
- 그림자는 떠 있는 것(팝업, 하단 시트, 토스트)에만 준다. 모든 카드에 그림자를 주면 계층이 사라진다.
- 글꼴은 하나(한글은 Pretendard, 없으면 맑은 고딕). 크기 척도는 12, 13, 15, 17, 20, 24 정도.
- 상태를 색만으로 나타내지 않는다. 뱃지에 글자를 함께 쓴다(발송, 실패, 임시저장).
- 이모지와 그라데이션은 쓰지 않는다. 아이콘은 선 아이콘 한 벌만.
- 다크 모드는 토큰을 한 번 더 정의하는 것으로 끝낸다. 데모에서 필수는 아니다.

## 화면 글은 최소로

좋은 화면은 글을 읽지 않아도 알아본다. 모양, 자리, 배지, 숫자가 설명을 대신한다. 설명 문장이 필요하다고 느껴지면 디자인을 먼저 고친다.

- 화면에 늘 떠 있는 글은 **제목, 라벨, 값, 버튼 이름**뿐이다. 동작 설명과 정책 설명 문장은 두지 않는다.
- 상태는 문장이 아니라 **배지, 아이콘, 숫자**로 보인다. "7일 안에 받지 못하면 만료됩니다" 대신 대기 배지 옆에 `7일`.
- 할 수 있는 일은 **버튼이 있는지 없는지로** 보여 준다. 취소할 수 있는 행에만 취소 버튼이 있으면 "대기 중인 작업만 취소할 수 있습니다" 는 필요 없다.
- 정책(재시도 횟수, 보관 기간, 저장 방식)은 화면이 아니라 도움말이나 문서에 둔다. 꼭 보여야 하면 `ⓘ` 툴팁 하나.
- 안내 문장은 **그 상황에서만** 나타난다. 오류, 빈 목록, 확인 창, 처음 쓰는 기능. 평소 화면에는 없다.
- 페이지 부제는 없애거나 한 구절로 줄인다. 메뉴 이름과 제목이 이미 무엇을 하는 화면인지 말한다.
- 쓴 문장마다 지워 본다. 지워도 사용자가 다음에 할 일을 안다면 지운다. 한 화면의 안내 문장은 0개가 목표, 많아야 1개.

| 설명이 많은 판 (실제로 지적받은 예) | 줄인 판 |
|---|---|
| `동기화가 늦은 PC 2대 · Google 인증 정상 · 본문은 저장하지 않고 원본으로 이동합니다` 를 목록 아래 한 줄로 | 문제가 있을 때만 상단 배너. 정상 상태와 저장 방식 설명은 없앤다 |
| `들어갈 곳: 예비 PC · 문서\…\미분류\ 이 PC 에 프로젝트 폴더를 정하려면 PC 에이전트 설정에서 지정하세요` | 경로 한 줄 + `기본 폴더` 배지. 설정 방법은 폴더 관리 화면의 빈 상태에서만 |
| `대기 중인 작업만 취소할 수 있습니다. 실패하면 3번까지 다시 보냅니다. 7일 안에 받지 못한 파일은 만료되고 메일로 알려 드립니다.` | 없앤다. 취소 버튼은 대기 행에만, 실패는 `실패 2/3` 배지, 대기는 `7일` 배지 |
| PC 카드 안에 `프로젝트 폴더 없음 · 기본 폴더로` 문장 | 카드에 폴더 아이콘과 경로, 없으면 흐린 `기본 폴더` 배지 |

## 배치와 경고 창

- **웹도 한 열을 기본으로 한다.** 폼과 목록을 좌우로 나란히 두지 않는다. 한 화면에 두 가지 일이 있으면 탭으로 나눈다(예: 파일 전달의 [보내기 | 전달 상태]). 설정의 왼쪽 하위 메뉴도 빼고 카드를 세로로 쌓는다.
- 카드 목록도 한 열. 폭이 남는다고 2열로 채우지 않는다. 폭은 같은 화면의 다른 탭·표와 맞춰 **본문 폭을 채운다**(fill). 720px 로 묶었다가 "어중간해 보인다" 는 지적을 받았다(2026-09-29).
- **경고 창(확인 창)**: 경고 아이콘을 제목 **앞에** 가로로 둔다. 제목은 "정말 ○○ 하시겠습니까?", 결과가 따를 때만 설명 한 줄, 아래에 [취소] + 빨간 동작 버튼. 되돌릴 수 있는 동작(로그아웃)은 검정 버튼.
- 경고 창 제목에 고유 이름(파일명, PC 이름, 프로젝트 이름)을 넣지 않는다. 대상의 종류로 부른다. "정말 파일 전달을 취소하시겠습니까?", "정말 PC의 연결을 해제하시겠습니까?", "정말 폴더를 삭제하시겠습니까?".
- 리딩 아이콘(leading icon)은 **제목 두 줄 높이**에 맞춘다(행간 × 2. 제목 18px·행간 26px 이면 52px). 제목은 아이콘과 **세로 가운데 정렬**(교차축 가운데, CSS `align-items: center`, Figma 오토 레이아웃 Align center). 설명은 제목 아래에 제목 시작선과 맞춰 둔다(아이콘 폭 + 간격만큼 들여쓰기). 이 아이콘 + 글 묶음 배치를 미디어 오브젝트(media object) 패턴이라 부른다.
- 닫기 버튼(✕)은 헤더 줄에 넣지 않고 창의 우측 상단에 고정한다. 헤더를 세로 가운데 정렬하면 함께 내려와 어색해진다.
- 경고 창이 "붕 뜨지" 않게: 제목과 설명은 한 정렬선에 붙이고(간격 4px), 내용과 버튼 사이는 24px 로 벌린다. 버튼은 창 폭을 채우지 말고 오른쪽 정렬, 글자 폭만큼. 버튼 줄은 옅은 바탕과 위쪽 선을 둔 **푸터 띠**로 나눈다(사용자가 2026-09-28 푸터 띠를 골랐다). 모바일은 푸터 안에서 두 버튼을 같은 폭으로 채운다(누르기 쉽게).

## 데모 화면의 상태

화면은 비어 있는 모습으로 열지 않는다. 예시 데이터를 채워 무엇을 하는 화면인지 바로 보이게 한다. 예시라는 표시는 한 곳에 둔다.
각 목록 화면은 세 상태를 생각해 둔다. 데이터가 있을 때, 없을 때, 불러오는 중이거나 실패했을 때.

**긴 목록은 기기에 따라 나눠 보인다.** 웹은 페이지 넘기기(예시 프로젝트는 10건), 모바일은 끝까지 내리면 더 불러오기(5건)와 목록 끝 스피너. 검색·필터를 바꾸면 첫 쪽, 첫 묶음으로 돌아간다. 페이지나 스크롤 로딩을 보이려면 예시 데이터를 한 화면에 다 안 들어갈 만큼(4~5쪽) 채운다(2026-09-29).
보기 전용이라는 것이 편집 버튼이 없는 것으로 이미 보이면 "○○ 에서 관리" 같은 안내 배지를 달지 않는다. 같은 뜻을 두 번 말하는 셈이다.

## 점검표

- [ ] 화면마다 가장 먼저 볼 것이 하나인가
- [ ] 주 버튼이 한 화면에 하나인가
- [ ] 같은 동작이 모든 화면에서 같은 모양과 자리인가
- [ ] 위험한 동작에 확인 단계가 있는가
- [ ] 여러 단계 입력에 현재 단계가 보이는가
- [ ] 휴대폰 폭(360~400px)에서 가로 스크롤이 없는가
- [ ] 글과 배경의 대비가 충분한가
- [ ] 상태가 색과 글자로 함께 보이는가
- [ ] 웹 화면이 한 열인가. 좌우로 나눈 곳을 탭으로 바꿀 수 있는가
- [ ] 평소 화면에 설명 문장이 없는가. 있다면 지워도 할 일을 모르는 문장인가
- [ ] 긴 목록을 웹은 페이지로, 모바일은 스크롤 로딩으로 나눴는가
