# 화면 용어

## 왜 있는가

2026-09-28 에 와이어프레임을 여러 번 고쳤다. 사용자는 "아이콘을 제목 앞에", "x 표시는 원래 위치인 우측 상단에",
"내용이 붕 뜨는 느낌" 처럼 풀어서 말했고, 매번 "전문용어로 뭐라 해요?" 라고 물었다. 그리고 이렇게 정했다.

> 사용자와 대화하며 개선한 경험을 엮어 가며, 용어를 전혀 모르는 사용자가 조금씩 전문 용어를 학습해 갈 수 있게,
> 사용자가 요청한 개선 사항은 모두 전문 용어로 설명하고, 상황과 함께 기록한다.

용어를 알면 디자이너·개발자에게 한 문장으로 전할 수 있고, 다음 요청도 짧아진다.

## 들어 있는 것

| 파일 | 내용 |
|---|---|
| `SKILL.md` | 설명하는 법과 기록하는 법 |
| `용어집.md` | 쌓인 용어. 날짜순. 각 용어에 그때의 상황과 사용자가 한 말이 붙어 있다 |

## 설명하는 법

사용자가 화면 개선을 요청하면 고친 뒤 보고할 때 **요청마다** 한 줄씩 붙인다.

```
| 하신 말 | 용어 | 뜻 |
| x 표시는 우측 상단에 | 닫기 버튼 고정 (pinned close button) | 헤더 정렬과 상관없이 창 모서리에 둔다 |
```

- 용어는 한국어 이름을 먼저, 영어를 괄호에 쓴다. 뜻은 한 문장. 사용자의 말을 그대로 옮겨 적는다.
- **새 용어는 한 번에 세 개까지만** 설명한다. 더 있으면 가장 중요한 셋만 표에 넣고 나머지는 용어집에만 적는다.
- 사용자가 이미 **직접 쓴 용어**(용어집에 `직접 씀` 표시)는 다시 풀이하지 않는다. 그 용어로 바로 말한다.
- 디자이너에게 전할 문장을 하나 붙이면 좋다. 예: "경고 창 헤더를 가로 배치로, 리딩 아이콘은 제목과 세로 가운데 정렬로."
- 원인을 물으면(예: "붕 뜨는 느낌") 원인도 용어로 나눈다. 느낌을 만드는 원리(정렬선, 근접성)를 알려 주면 다음에 사용자가 스스로 짚는다.
- 문장 규칙은 [[plain-writing]] 을 따른다. 짧게.

## 기록하는 법

설명한 용어는 그 턴에 `용어집.md` 에 적는다. 확인을 기다리지 않는다(기록은 허가 없이 바로 한다).

```markdown
### 용어 (영어)
- 날짜: YYYY-MM-DD · 화면: <어느 화면에서>
- 하신 말: "<사용자 원문>"
- 상황: <무엇이 문제였고 어떻게 고쳤는지 한두 문장>
- 뜻: <한 문장>
- 전하는 말: "<디자이너에게 할 한 문장>"
- 이어서: <같이 알면 좋은 용어 하나>
```

- 이미 있는 용어가 다시 나오면 새 항목을 만들지 않고 그 항목에 `- 다시: 날짜 · 상황` 한 줄만 더한다.
- 사용자가 그 용어를 자기 말로 쓰면 항목 제목 옆에 `· 직접 씀 (날짜)` 을 붙인다. 이것이 학습 진도다.
- 용어집 맨 위의 "익힌 순서" 표에도 한 줄 더한다.
- 프로젝트 고유명(사람 이름, 회사명)은 쓰지 않는다. 화면 이름과 상황만 적는다.

## 사용자 말 → 용어 빨리 찾기

자주 나온 말은 `용어집.md` 끝의 "빨리 찾기" 표에 있다. 사용자가 풀어서 말하면 먼저 여기서 찾는다.
