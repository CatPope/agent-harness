# 발표 자료 만들기

## 왜 있는가

2026-09-27 에 함께 개발할 팀원에게 보여 줄 프로젝트 제안 발표를 만들었다. 사용자 지시는 둘이었다.
"그림·사진·그래프 등 시각자료가 많고, 글자는 최대한 짧고 직관적인 단문체." 그리고 참고 글
프레젠티 「좋은 PPT 만드는 법」(https://presenti.ai/kr/blog/how-to-make-a-good-ppt/, 2026-09-27 확인).
이 스킬은 그 규칙과 양식 PPTX 를 채우는 방법을 남긴다.

## 들어 있는 것

| 경로 | 내용 |
|---|---|
| `templates/[양식] 프로젝트 제안서.pptx` | 처음 적용한 발표의 양식 원본(508 × 286 mm). 읽기만 한다 |
| `scripts/pptx_diff.py` | 생성본과 사람이 고친 판을 장·도형 단위로 비교한다 |
| `examples/deck_build.py` | 그 발표의 생성기를 가명으로 옮긴 참고용. 화면 캡처와 구성 그림을 전제해 그대로는 돌지 않는다 |

처음 한 번 `setup.ps1`(윈도) 또는 `setup.sh` 를 돌린다. python-pptx, Pillow, matplotlib 를 깐다.

🔴 **양식 고르는 순서.** 사용자가 따로 준 양식이 있으면 그것을 쓴다. `templates/` 의 양식은 사용자 양식이 없을 때만 쓴다.
먼저 사용자에게 받은 양식이 있는지 확인하고, 있으면 생성기에 생성기 맨 위 `TPL` 로 그 경로를 준다.
생성기는 양식의 구조(본보기 문단·표·도형 번호)를 전제한다. 다른 양식이면 구조를 먼저 덤프하고 생성기를 맞춘다.

## 규칙

| 규칙 | 출처 |
|---|---|
| 한 장에 한 메시지. 제목과 소제목만 읽어도 흐름이 보인다 | 프레젠티 |
| 긴 문단은 결론 한 줄 + 근거 2~3개 + 시각자료로 바꾼다 | 프레젠티 |
| 장식 사진보다 제품 화면, 과정 그림, 비교 그림, 차트 | 프레젠티 |
| 차트에는 해석 한 줄을 붙인다. 숫자만 두지 않는다 | 프레젠티 |
| 글꼴은 제목용과 본문용 둘. 강조색은 적게 | 프레젠티 |
| 글과 그림의 시작선을 맞추고 요소 사이를 넉넉히 띄운다 | 프레젠티 |
| 시각자료를 많이. 글은 짧은 단문. 한 줄에 15자 안팎 | 사용자 09-27 |
| 문장 규칙(줄표 설명 금지, 굵은 글씨 절제, 대구·"핵심은" 금지) | [[plain-writing]] |
| 양식이 있으면 그 파일에 채운다. 양식의 번호 머리·절 이름은 그대로 둔다 | [[plain-writing]] 규칙 2 |
| 요청에서 뺀 항목은 목차와 본문에서 모두 뺀다(예: 예산) | 사용자 09-27 |

## 데이터 없는 숫자를 만들지 않는다

양식의 예시 그래프(고객 이탈률 23%, 업무 효율 65% 같은 값)는 지운다. 잰 값이 없으면 이렇게 바꾼다.
- 현황: 지금 흐름을 단계 그림으로, 비슷한 서비스는 기능 비교표로.
- 기대 효과: 요구사항서의 목표 수치(전화 0통, 10초, 1번)를 큰 글자로. 비교 막대는 "설계 흐름 기준" 이라고 적는다.
- 사람 사진 자리: 모르는 사람의 예시 사진은 이니셜 원 도형으로 바꾼다. 실제 사진은 받았을 때만 넣는다.
- 가짜 연락처, 회사 이름, 예시 주소는 모두 지운다.

## 만드는 순서

1. 양식을 PowerPoint COM 으로 PNG 로 뽑아 본다. 장마다 무엇을 보여 주는 틀인지 적는다.
2. python-pptx 로 장마다 도형 id, 위치(mm), 글을 덤프한다. 그룹 안의 사진·아이콘도 본다.
3. 목차를 우리 내용으로 짜서 사용자에게 보인다(양식 장 → 우리 내용 → 근거 자료 표).
4. 확정되면 생성기를 쓴다. 내용은 생성기 맨 위 상수에 둔다. 글은 짧은 단문만.
5. 생성 → PowerPoint 로 열기 → 모든 장 PNG → 2×2 묶음으로 눈으로 본다. 넘침, 줄바꿈, 가려짐, 남은 예시 글자를 찾는다.
6. `plain-writing/scripts/check_tone.py` 를 PPTX 에 돌린다.
7. `<이름>_vX.Y.Z.pptx` 로 저장하고 진행 기록에 적는다.

## 예시 생성기

`examples/deck_build.py <버전>` 이 `templates/[양식] 프로젝트 제안서.pptx` 를 채운 방식이다. 자기 발표에 맞게 옮겨 쓴다.

| 부분 | 방법 |
|---|---|
| 글 바꾸기 | `set_text(도형, 줄 목록, size=)`. 첫 글자 서식을 살리고 글만 바꾼다 |
| 도형 찾기 | 양식 슬라이드마다 `shape_id`. 양식이 바뀌면 2단계 덤프부터 다시 |
| 그림 | matplotlib, 양식 색(#575849, #828A73, #97988E, #DEDEDC). 그림 크기는 넣을 자리의 mm 로 잡아 글자 pt 가 실제 크기가 되게 |
| 화면 | 화면 데모 HTML 을 `?shot&dev=mob#화면ID` 로 열어 컬러로 캡처(번호·흑백 없이). 원본은 [[screen-design-doc]] |
| 새 장 | `duplicate()` 로 기존 장의 배경과 틀 도형만 복제. 그림 관계(r:embed)도 옮긴다 |
| 장 순서 | `move()`, 뺄 장은 `drop_rel` + `sldIdLst` 에서 제거 |
| 마무리 | 슬라이드마다 도형 id 를 다시 매긴다. 겹치면 PowerPoint 가 파일을 못 연다 |

## 함정 (2026-09-27 실제로 겪음)

- **양식 크기를 먼저 본다.** 이 양식은 508 × 286 mm 로 보통 슬라이드의 1.5 배다. 18pt 가 작게 보였다. 본문 22~26pt, 설명 17~20pt 로 잡았다.
- **양식의 그림 자리 좌표를 믿지 않는다.** 그래프 그림이 머리 띠까지 덮는 크기였다. 머리 띠 아래로 옮겨 넣었다.
- **도형 번호와 화면 위치가 다를 수 있다.** 그림 18 이 오른쪽, 19 가 왼쪽이었다. 덤프의 좌표로 짝을 맞춘다.
- **사진 원 그룹의 사진은 원보다 크게 잘려 있다.** 그림만 바꾸면 이니셜이 잘린다. 그룹을 지우고 원 도형을 새로 넣는다.
- **좁은 칸(꼬리말 알약, 목차)은 줄바꿈된다.** 긴 주소는 짧은 이름으로 바꾼다.
- **matplotlib 막대 그래프의 y축 글자가 왼쪽에서 잘린다.** axes 왼쪽 여백을 0.14 이상 준다.

## 사용자가 PPT 를 직접 고쳤을 때

1. 생성기의 `OUT` 을 임시 폴더로 바꿔 같은 버전을 다시 만든다. 사용자 파일은 덮어쓰지 않는다.
2. `python <스킬>/scripts/pptx_diff.py <생성본> <사용자본>` 으로 장·도형별 차이를 본다.
3. 글·위치·그림 차이를 생성기 상수에 되먹이고 다시 비교한다. 텍스트 상자 높이만 다른 것은 PowerPoint 자동 맞춤이라 무시한다.
4. 사용자가 한 곳만 고쳐 다른 곳과 어긋나면(예: 제목만 바꾸고 목차는 그대로) 고치지 말고 물어본다.
