# 발표 자료 만들기

## 왜 있는가

2026-09-27 에 함께 개발할 팀원에게 보여 줄 프로젝트 제안 발표를 만들었다. 사용자 지시는 둘이었다.
"그림·사진·그래프 등 시각자료가 많고, 글자는 최대한 짧고 직관적인 단문체." 그리고 참고 글
프레젠티 「좋은 PPT 만드는 법」(https://presenti.ai/kr/blog/how-to-make-a-good-ppt/, 2026-09-27 확인).
이 스킬은 그 규칙과 양식 PPTX 를 채우는 방법을 남긴다.

## 들어 있는 것

| 경로 | 내용 |
|---|---|
| `templates/[양식] 프로젝트 제안서.pptx` | 처음 적용한 발표의 양식 원본(508 × 286 mm). 읽기만 한다 |
| `scripts/pptx_diff.py` | 생성본과 사람이 고친 판을 장·도형 단위로 비교한다 |
| `examples/deck_build.py` | 그 발표의 생성기를 가명으로 옮긴 참고용. 화면 캡처와 구성 그림을 전제해 그대로는 돌지 않는다 |

처음 한 번 `setup.ps1`(윈도) 또는 `setup.sh` 를 돌린다. python-pptx, Pillow, matplotlib 를 깐다.

🔴 **양식 고르는 순서.** 사용자가 따로 준 양식이 있으면 그것을 쓴다. `templates/` 의 양식은 사용자 양식이 없을 때만 쓴다.
먼저 사용자에게 받은 양식이 있는지 확인하고, 있으면 생성기에 생성기 맨 위 `TPL` 로 그 경로를 준다.
생성기는 양식의 구조(본보기 문단·표·도형 번호)를 전제한다. 다른 양식이면 구조를 먼저 덤프하고 생성기를 맞춘다.

## 규칙

| 규칙 | 출처 |

| 긴 문단은 결론 한 줄 + 근거 2~3개 + 시각자료로 바꾼다 | 프레젠티 |
| 장식 사진보다 제품 화면, 과정 그림, 비교 그림, 차트 | 프레젠티 |
| 차트 해석은 장 제목이나 말로 한다. 그림 옆에 해석 줄을 덧붙이지 않는다 | 사용자 10-15. 프레젠티의 "해석 한 줄" 을 바꿨다 |
| 양식이 있으면 양식 글꼴을 그대로 쓴다. 없을 때만 제목용과 본문용 둘. 강조색은 적게 | 사용자 10-15, 프레젠티 |
| 글과 그림의 시작선을 맞추고 요소 사이를 넉넉히 띄운다 | 프레젠티 |
| 시각자료를 많이. 글은 짧은 단문. 한 줄에 15자 안팎 | 사용자 09-27 |
| 문장 규칙(줄표 설명 금지, 굵은 글씨 절제, 대구·"핵심은" 금지) | [[plain-writing]] |
| 양식이 있으면 그 파일에 채운다. 양식의 번호 머리·절 이름은 그대로 둔다 | [[plain-writing]] 규칙 2 |
| 요청에서 뺀 항목은 목차와 본문에서 모두 뺀다(예: 예산) | 사용자 09-27 |

## 양식 칸만 채운다 (사용자 2026-10-15)

> 사용자: *"필요 없는 추가 설명은 AI 느낌이 너무 남. 사람은 웬만해서 템플릿만 채우고 말로 설명하거나,
> 내용이 많고 중요하다면 따로 페이지를 만들어서 다룸. 차라리 ppt와 함께 볼 설명 문서를 별개로 만들어서 제공."*

- 양식에 있는 칸만 채운다. 칸 밖에 라벨, 각주, 출처, 측정일, 요약 문장 글상자를 더하지 않는다.
  "업무 현장의 문제", "요구사항" 같은 표 머리 라벨, "(3주차 실측)" 같은 각주, 표 아래 결론 한 줄이 실제로 지적받았다.
- 내용이 많고 중요하면 장을 하나 더 만든다. 한 장에 설명을 늘리지 않는다.
- 말로 할 것은 **발표 설명 문서**(md)로 따로 준다. 장마다 말할 것, 질문이 나오면 쓸 숫자와 사실, 장별 시간을 적는다.
- 쓰지 않는 칸은 지운다. 빈 글상자를 남기거나 다른 말로 메우지 않는다.
- 요구사항 번호(FR-01, SR-01), 인수 기준 번호 같은 내부 번호를 장에 쓰지 않는다.
- 숫자는 그림에서 보이고 듣는 사람이 바로 이해하는 것만 둔다. 표 개수, 요구사항 개수 같은 셈은 빼고
  구조(관계도, 실제 문장)를 보인다. 그림 속 작은 출처, 측정일 글씨도 뺀다. 숫자는 질문이 나올 때 답한다.
- **양식 글꼴을 바꾸지 않는다.** Canva 같은 곳에서 받은 PPTX 는 글꼴을 파일 안에 넣어 둔다
  (`ppt/fonts/*.fntdata`, `presentation.xml` 의 `p:embeddedFontLst`). PC 에 설치되어 있지 않아도 PowerPoint 가 그린다.
  글꼴이 없다고 판단하기 전에 이 둘을 먼저 본다. 글자 크기는 넘칠 때만 줄인다.
- 발표 시간으로 장 수를 정한다. 한 장에 1분 안팎이다. 10~20분 발표면 표지와 끝 장을 넣어 15~17장이다.

## 진척을 보일 때 (사용자 2026-10-15)

- **완료는 검증까지 끝난 것만 센다.** 검증 중이면 진행 중, 검증 전이면 예정이다. 예정은 다음 계획 장에 넣는다.
- 계획보다 크게 앞선 것은 드러내지 않는다. 조금 앞선 정도는 괜찮다. 이 기준은 같은 사람이 내는 회의록과 보고서에도 같다.
- 그래프는 한눈에 읽히게 그린다. 계획 주차 막대에 상태 색(완료, 진행 중, 예정)을 칠하고 현재 선을 긋는 일정표가 낫다.
  전체 개수, 계획 개수, 완료 개수를 한 막대 묶음에 섞은 그래프는 읽기 어렵다고 지적받았다.
- 상태 색은 흑백 인쇄에서도 갈리게 채움, 빗금, 빈칸으로 나눈다. 범례는 상태 이름만 쓴다.

## HTML 로 만들 때 (Figma 틀, 사용자 2026-10-15)

사용자가 PPT 대신 "figma 컴포넌트 보고 html로 동적인 애니메이션 조금 추가해서" 만들라고 할 때가 있다. 그때도 위 규칙(칸만 채운다,
글꼴, 진척, 숫자)은 그대로다. 「양식」이 Figma 틀로 바뀔 뿐이다.

- **목차와 구성을 먼저 보이고 승인을 받는다.** 장마다 고른 Figma 틀 번호, 놓을 것, 움직임을 표로 보인다.
  틀 썸네일에 장 번호를 붙인 대응 그림을 함께 주면 고르기 쉽다.
- 틀을 고르는 법은 [[figma-mcp]] 의 「덱 파일에서 틀 고르기」를 따른다. 고른 틀만 디자인 정보를 읽는다.
- **글꼴.** 틀 글꼴에 한글이 없으면 영문과 숫자는 틀 글꼴(무료일 때)을 쓰고, 한글은 모양이 가까운 무료 글꼴을 고른다.
  넓고 굵은 영문 제목에는 G마켓 산스, 본문에는 Pretendard 가 맞았다. 유료 글꼴은 쓰지 않는다. 고를 때 사용자에게 묻는다.
- **파일 하나로 낸다.** CSS, JS, 글꼴, 그림을 data URI 로 넣어 인터넷 없이 열리게 한다. 글꼴은 발표에 나오는 글자만 남긴다
  (fontTools subset, woff). 원본(html, css, js)과 묶는 스크립트를 따로 둔다.
- **움직임은 의미가 있는 곳에만.** 흐름(점이 길을 따라감), 사라짐(원이 흐려짐), 입력(명령 타자), 일정(막대가 자람)처럼
  말할 내용을 보여 주는 곳에 둔다. 나머지 장은 나타나기만 한다. R 키로 다시 틀 수 있게 한다.
- **움직임이 끝난 모습이 기본이다.** HTML 의 처음 상태를 끝난 모습으로 쓰고, 움직임은 장에 들어올 때만 거꾸로 숨겼다가 보인다.
  `?static` 과 인쇄는 끝난 모습만 쓴다. 인쇄본 PDF 는 같은 HTML 에서 뽑는다(Playwright `page.pdf`, 1920 x 1080 px).
- **확인.** 장마다 끝난 모습 그림, 움직임 중간 그림 몇 장, PDF 쪽 그림을 떠서 눈으로 본다. 키보드 넘기기, 크게 보기,
  작은 화면 맞춤도 브라우저로 눌러 본다. 장 글은 뽑아서 `check_tone.py` 를 돌린다.

함정 (2026-10-15 겪음)
- 주소의 `#번호` 만 바뀌면 페이지가 다시 읽히지 않는다. 처음에만 번호를 읽으면 확인 그림이 모두 1장으로 찍힌다. `hashchange` 를 받는다.
- 크기가 없는 `position: absolute` 상자 안의 글은 한 글자씩 세로로 쪼개진다. 상자에 크기를 주거나 `white-space: nowrap`.
- `repeating-linear-gradient` 로 그린 점선은 PDF 에서 굵은 파선이 된다. `border-top: 2px dotted` 를 쓴다.
- woff2 원본은 brotli 모듈이 없으면 fontTools 가 못 읽는다. OTF, TTF 원본을 받는다.
- 데모 캡처를 쓸 때 위의 데모 조작 띠와 관계도 그림의 제목 줄은 잘라 낸다. 장 제목과 겹친다.

## 데이터 없는 숫자를 만들지 않는다

양식의 예시 그래프(고객 이탈률 23%, 업무 효율 65% 같은 값)는 지운다. 잰 값이 없으면 이렇게 바꾼다.
- 현황: 지금 흐름을 단계 그림으로, 비슷한 서비스는 기능 비교표로.
- 기대 효과: 요구사항서의 목표 수치(전화 0통, 10초, 1번)를 큰 글자로. 비교 막대는 "설계 흐름 기준" 이라고 적는다.
- 사람 사진 자리: 모르는 사람의 예시 사진은 이니셜 원 도형으로 바꾼다. 실제 사진은 받았을 때만 넣는다.
- 가짜 연락처, 회사 이름, 예시 주소는 모두 지운다.

## 만드는 순서

0. **평가표나 발표 조건(시간, 장 수, 파일 형식, 배점)을 먼저 찾는다.** 없으면 사용자에게 언제 나오는지 묻고, 나오면 그 조건으로 구성부터 다시 대조한다.
   배점 항목마다 그것을 보여 줄 장이 있는지 표로 맞춘다. 형식은 평가표가 정한 것을 따른다(「PowerPoint」 라고 적혀 있으면 HTML 로 바꾸지 않는다).
1. 양식을 PowerPoint COM 으로 PNG 로 뽑아 본다. 장마다 무엇을 보여 주는 틀인지 적는다.
2. python-pptx 로 장마다 도형 id, 위치(mm), 글을 덤프한다. 그룹 안의 사진·아이콘도 본다.
3. 목차를 우리 내용으로 짜서 사용자에게 보인다(양식 장 → 우리 내용 → 근거 자료 표). 🔴 **구성안 단계에서도 이 스킬의 규칙과 그 프로젝트의 지적 목록을 장마다 대조하고, 대조 표를 구성안에 함께 둔다.** 글로 쓴 계획에 칸 밖 라벨, 결론 줄, 계획끼리 겹친 그래프가 들어가면 그대로 다시 지적받는다.
4. 확정되면 생성기를 쓴다. 내용은 생성기 맨 위 상수에 둔다. 글은 짧은 단문만.
5. 생성 → PowerPoint 로 열기 → 모든 장 PNG → 2×2 묶음으로 눈으로 본다. 넘침, 줄바꿈, 가려짐, 남은 예시 글자를 찾는다.
6. `plain-writing/scripts/check_tone.py` 를 PPTX 에 돌린다.
7. 발표 설명 문서(md)를 쓴다. 장에서 뺀 설명, 질문이 나오면 쓸 숫자, 장별 시간을 담는다. 같은 검사를 돌린다.
8. `<이름>_vX.Y.Z.pptx` 로 저장하고 진행 기록에 적는다.

## 예시 생성기

`examples/deck_build.py <버전>` 이 `templates/[양식] 프로젝트 제안서.pptx` 를 채운 방식이다. 자기 발표에 맞게 옮겨 쓴다.

| 부분 | 방법 |
|---|---|
| 글 바꾸기 | `set_text(도형, 줄 목록, size=)`. 첫 글자 서식을 살리고 글만 바꾼다 |
| 도형 찾기 | 양식 슬라이드마다 `shape_id`. 양식이 바뀌면 2단계 덤프부터 다시 |
| 그림 | matplotlib, 양식 색(#575849, #828A73, #97988E, #DEDEDC). 그림 크기는 넣을 자리의 mm 로 잡아 글자 pt 가 실제 크기가 되게 |
| 화면 | 화면 데모 HTML 을 `?shot&dev=mob#화면ID` 로 열어 컬러로 캡처(번호·흑백 없이). 원본은 [[screen-design-doc]] |
| 새 장 | `duplicate()` 로 기존 장의 배경과 틀 도형만 복제. 그림 관계(r:embed)도 옮긴다 |
| 장 순서 | `move()`, 뺄 장은 `drop_rel` + `sldIdLst` 에서 제거 |
| 마무리 | 슬라이드마다 도형 id 를 다시 매긴다. 겹치면 PowerPoint 가 파일을 못 연다 |

## 함정 (2026-09-27 실제로 겪음)

- **양식 크기를 먼저 본다.** 이 양식은 508 × 286 mm 로 보통 슬라이드의 1.5 배다. 18pt 가 작게 보였다. 본문 22~26pt, 설명 17~20pt 로 잡았다.
- **양식의 그림 자리 좌표를 믿지 않는다.** 그래프 그림이 머리 띠까지 덮는 크기였다. 머리 띠 아래로 옮겨 넣었다.
- **도형 번호와 화면 위치가 다를 수 있다.** 그림 18 이 오른쪽, 19 가 왼쪽이었다. 덤프의 좌표로 짝을 맞춘다.
- **사진 원 그룹의 사진은 원보다 크게 잘려 있다.** 그림만 바꾸면 이니셜이 잘린다. 그룹을 지우고 원 도형을 새로 넣는다.
- **좁은 칸(꼬리말 알약, 목차)은 줄바꿈된다.** 긴 주소는 짧은 이름으로 바꾼다.
- **matplotlib 막대 그래프의 y축 글자가 왼쪽에서 잘린다.** axes 왼쪽 여백을 0.14 이상 준다.

2026-10-15 에 겪은 것.

- **글을 바꾸는 함수가 글꼴 이름까지 덮으면 양식 글꼴이 사라진다.** 글과 크기만 바꾸고 `a:latin`, `a:ea` 는 건드리지 않는다.
- **선 도형에도 글상자가 있다.** 칸을 위치로 찾으면 같은 높이의 선에 글이 들어간다. 복제한 도형은 새 id 로 직접 잡는다.
- **양식 표의 칸마다 자간이 다를 수 있다.** 오른쪽 표 칸만 `spc` 가 없어 글자 간격이 달랐다. 다른 표에서 칸을 가져오면 자간을 맞춘다.
- **양식 표의 선은 굵기가 다르다.** 위, 아래는 굵은 선이고 머리 아래와 줄 사이는 가는 선이었다. 표를 늘릴 때 선마다 `a:ln w` 를 보고 자리를 정한다.
- **화면 캡처는 양식 그림 칸에 그대로 넣으면 글자가 안 읽힌다.** 그림 칸을 넓히고 옆 글 칸을 좁힌다.
  그림은 넣을 자리의 mm 크기로 그려야 그림 속 글자 pt 가 장에서도 그대로다.

## 사용자가 PPT 를 직접 고쳤을 때

0. **다시 만들기 전에 늘 확인한다.** `~$<파일>` 잠금 파일과 `POWERPNT` 프로세스가 있으면 열려 있는 것이다. 쓰지 말고 닫아 달라고 한다.
   파일 수정 시각이 마지막 생성보다 뒤면 사용자가 고친 것이다. 아래 1~3 으로 대조해 생성기에 옮기고, 사용자 판은 `이전 판/<이름>_<시각>_사용자수정.pptx` 로 남긴 뒤 만든다.
   사용자가 장을 지운 것도 수정이다. 생성기의 장 목록에서 빼고 이유를 주석으로 남긴다.
1. 생성기의 `OUT` 을 임시 폴더로 바꿔 같은 버전을 다시 만든다. 사용자 파일은 덮어쓰지 않는다.
2. `python <스킬>/scripts/pptx_diff.py <생성본> <사용자본>` 으로 장·도형별 차이를 본다.
3. 글·위치·그림 차이를 생성기 상수에 되먹이고 다시 비교한다. 텍스트 상자 높이만 다른 것은 PowerPoint 자동 맞춤이라 무시한다.
4. 사용자가 한 곳만 고쳐 다른 곳과 어긋나면(예: 제목만 바꾸고 목차는 그대로) 고치지 말고 물어본다.

## 그림 고를 때

- 예정 기능(일정상 아직 만들 때가 아닌 것)의 실제 화면 캡처를 쓰지 않는다. 이미 만든 티가 나 "왜 벌써 만들었냐" 는 말을 듣는다. 설계 산출물(와이어프레임)을 쓴다.
- 이미지 폴더의 그림은 이름만 보고 고르지 않는다. 열어서 설계 그림인지 실제 화면인지 확인한다.
- 큰 장(508 mm 폭)에 넓게 까는 그림은 그림 안 글자를 20pt 이상으로 그린다. 템플릿 바탕이 순백이 아니면 그림 바탕을 투명하게 둔다.
- 데이터 설계(ERD)처럼 발표자가 설명하기 어려운 그림은 빼고, 질문이 나오면 답할 두세 줄을 발표 설명에 둔다.

## 그림을 새로 그리거나 고칠 때

- 🔴 **같은 덱의 다른 그림 원본부터 연다.** 도구(Mermaid, matplotlib), 배치기(Mermaid 기본 dagre 인지 ELK 인지),
  칸 모양, 배색의 뜻(예: 흰 바탕 파란 테두리 = 시스템 안 처리, 회색 = 바깥 끝점), 선 이름 색을 뽑아 그대로 따른다.
  그림 하나만 다른 도구나 다른 배치기로 그리면 바로 "혼자 디자인이 다르다"는 말을 듣는다.
- 순서도 기본형(꼭짓점에서 나가는 판단 선 등)과 덱의 통일감이 부딪히면 통일감을 먼저 맞추고, 남는 차이를 알린다.
- 구조도가 여러 장이면 같은 사실을 같은 이름, 같은 화살표 방향으로 그린다. 그리기 전에 실제 코드와 대조한다
  (없는 기능의 선, 주체가 틀린 화살표가 실제로 들어가 있었다).
- 그림만 갈아 끼울 때는 백업 → 열린 파일 확인 → 장 하나만 교체 → PowerPoint 로 장을 그림으로 뽑아 눈으로 본다.
