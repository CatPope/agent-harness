# 과제제안서 · 요구사항서 만들기

## 왜 있는가

2026-09-24 ~ 09-27 에 한 프로젝트(모임 관리 앱, 9주, 네 명)의 과제제안서와 요구사항서를 양식에 맞춰 여러 판 냈다.
양식은 사용자가 받은 교육 과정의 제안서와 요구사항서였고, 사용자가 판마다 내용을 고쳤다.
손으로 채우면 판을 올릴 때마다 서식이 무너진다. 그래서 내용은 파이썬 상수에 두고 양식에서 서식을 빌려 매번 새로 만든다.

## 들어 있는 것

| 경로 | 내용 |
|---|---|
| `templates/[양식] 요구사항서.docx` | 요구사항서 양식. 주석을 단 안내판이다. 읽기만 한다 |
| `templates/[양식] 과제제안서.docx` | 과제제안서 양식. 한글 HWPX 원본을 `hwpx_docx.py` 로 바꾼 것이다. 읽기만 한다 |

두 양식은 받은 원본에서 개인정보만 바꿨다. 이름은 홍길동, 학번은 0, 기업명은 예시회사, 지도자 이름은 ○ 로 두었다.
본문 예시 글과 기관 로고는 원본 그대로다. 생성기는 이 칸들을 쓰지 않아 바꾸기 전과 같은 결과를 낸다(2026-09-28 대조).
| `scripts/req_build.py` | 요구사항서 생성기. 내용은 `BODY` 상수 |
| `scripts/proposal_build.py` | 과제제안서 생성기. 내용은 파일 안의 상수 |
| `scripts/hwpx_docx.py` | HWPX 를 읽어 DOCX 로 그리는 변환기이자 렌더러 |
| `scripts/arch_build.py` | 구성 아키텍처 그림(PNG). 요구사항서 3.11 에 들어간다 |
| `scripts/fill_toc.ps1` | Word 로 목차의 `#` 를 쪽 번호로 바꾸고 PDF 를 뽑는다 |
| `examples/` | 위 생성기로 만든 예시 결과. 사람 이름은 가명이다(요구사항서 17쪽, 과제제안서 10쪽, 그림 1장) |

생성기의 내용 상수는 예시 프로젝트의 것이다. 자기 프로젝트에 쓸 때는 상수를 바꾼다.
처음 한 번 `setup.ps1`(윈도) 또는 `setup.sh` 를 돌린다. python-docx, lxml, matplotlib 를 깐다.

## 만드는 순서

결과는 실행한 폴더의 `out/` 에 쌓인다. 다른 곳에 두려면 환경 변수 `OUT_DIR` 을 준다.

```powershell
python <스킬>\scripts\arch_build.py "out\구성 아키텍처.png"     # 3.11 그림. 다른 그림이면 ARCH_PNG
python <스킬>\scripts\req_build.py                              # out\[1차] 요구사항서_v<VER>.docx
python <스킬>\scripts\proposal_build.py                         # out\[1차] 과제제안서_v<VER>.docx
<스킬>\scripts\fill_toc.ps1 -Files "<전체 경로 docx>", "<전체 경로 docx>"   # 목차 쪽 번호 + %TEMP% 에 PDF
```

1. 판 번호를 정하고 생성기 맨 위 `VER`, `DATE` 를 고친다. 이전 판은 같은 폴더의 `레거시/` 로 옮긴다.
2. 내용 상수를 고친다. 요구사항서는 `BODY`, 표 열 폭은 `WIDTHS`.
3. 그림, 요구사항서, 과제제안서 순으로 만든다.
4. `fill_toc.ps1` 로 목차를 채운다. 결과 줄의 `missing []` 가 비어 있어야 한다.
5. PDF 를 PNG 로 뽑아 눈으로 본다. 표지, 목차, 그림, 표가 넘치지 않는지.
6. [[plain-writing]] 의 `check_tone.py` 로 문장을 검사한다. 양식이 정한 `용어 : 설명`, `목적:` 콜론은 그대로 둔다.

## 요구사항서 생성기가 하는 판단

- 양식은 문단 스타일이 전부 Normal 에 직접 서식이다. 글자로 본보기 문단을 찾아 deepcopy 한 뒤 글자만 바꾼다.
- 표는 양식의 표(머리행 + 데이터행 1개)를 본보기로 두고 행을 복제한다.
- 양식 표는 열 폭이 전부 같다. ID 열이 넓어 본문이 세 줄로 접혀서 `WIDTHS` 로 비율을 준다.
- 양식 표 글자 9pt 는 작아서 읽기 힘들다는 지적을 받았다. `TABLE_SZ` 로 10.5pt 로 바꾼다. 본문은 11pt.
- FR·VR 번호는 `BODY` 의 표 순서가 정본이다. 항목을 끼워 넣으면 뒤 번호가 밀린다. 주석, 부록 A, VR 참조를 같이 고친다.
- 목차 문단에 오른쪽 점선 탭을 넣는다. 양식의 정적 목차는 탭 정지가 없어 쪽 번호가 제목 바로 뒤에 붙는다.
- 양식 첫 데이터행의 굵은 서식과 `목적:` 문단의 굵기는 `strip_bold` 로 뺀다.
- 빈 문단 본보기는 쪽 나눔이 없는 것으로 고른다. 쪽 나눔이 든 빈 문단을 썼다가 42쪽이 된 적이 있다.
- 양식 본문에 없는 절(3.5, 3.13, 3.14)은 목차에서도 뺀다. 양식 주석이 필요 없는 목차는 빼라고 한다.
- 절 제목이 쪽 끝에 홀로 남으면 `('pagebreak',)` 를 앞에 넣는다(3.11).

## 과제제안서 생성기가 하는 판단

- HWPX 원본이 `templates/` 에 있으면 거기서 쪽 여백, 글꼴, 표 테두리, 머리말을 읽는다. 없으면 DOCX 변환본의 `sectPr` 과 머리말에서 읽는다.
- 양식의 꼬리말(기관 로고, 과정명)은 다른 문서에 넣지 않는다.
- HWPX 의 줄 위치(`lineseg vertpos`)로 문단 앞 간격, 쪽 넘김, 줄 높이를 맞춘다. Word 배수 줄간격은 글꼴에 따라 커져 쪽이 밀린다.
- Word 는 꼬리말이 아래 여백보다 크면 본문을 밀어낸다. `footer_distance` 를 줄여 둔다.

## 함정 (실측)

- 목차는 필드가 아니라 글자다. 본문 제목과 목차 줄의 글자가 같아야 쪽 번호가 채워진다.
- `fill_toc.ps1` 은 PowerShell 에서 전체 경로로 부른다. bash 에서 `powershell -Command` 로 부르면 Word 가 멈춘 채 남았다.
  멈추면 Word 프로세스를 끝내고, 반쯤 채워진 docx 는 다시 만든 뒤 채운다.
- Word 로 저장하면 문서 속성의 마지막 저장자에 PC 계정 이름이 들어간다. 밖에 낼 파일이면 지운다.
- 한컴오피스 자동화(`HWPFrame.HwpObject`)는 열기는 되지만 `SaveAs("DOCX")` 가 False 를 돌려준다. 그래서 XML 을 직접 읽는다.
  PDF 저장은 대화상자에 걸려 프로세스가 남는다.
- 나눔고딕 같은 글꼴이 PC 에 없으면 Word 가 대체 글꼴로 그린다. 쪽 수가 한 쪽 안팎 달라질 수 있다.
- 양식 파일이 바뀌면(표 개수, 본보기 문단) 생성기가 `IndexError` 로 죽는다. 양식 구조를 다시 덤프하고 본보기 찾기를 고친다.
