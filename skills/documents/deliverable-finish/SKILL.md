# 산출물 마감

## 왜 있는가

생성 라이브러리로 만든 파일에는 **본문과 상관없는 흔적**이 남는다. 문장을 아무리 다듬어도
파일 속성을 열면 바로 보인다.

2026-10-02 에 python-pptx 로 만든 구성도 초안을 열어 보니 이랬다.

```
설명            generated using python-pptx
마지막 수정자    Steve Canny            ← python-pptx 개발자 이름
만든 날짜        2013-01-27             ← 라이브러리 기본 틀의 날짜
응용 프로그램    Microsoft Macintosh PowerPoint
문서 형식        On-screen Show (4:3)   ← 실제 슬라이드는 16:9
```

같은 날 **받은 양식 파일의 작성자가 `OpenAI`** 로 되어 있는 것도 나왔다. 양식을 그대로
따르면 남이 남긴 흔적까지 옮겨 붙는다.

검토는 내용을 보고, 이 스킬은 파일을 본다. 둘 다 거쳐야 마감이다.

## 순서

건너뛰지 않는다. 앞 단계에서 고친 것이 뒤 단계에서 다시 망가질 수 있으므로 이 순서다.

### 1. 외부 모델에게 검토받는다

**작성한 모델이 자기 결과를 검토하지 않는다.** 아래 순서로 있는 것을 쓴다.

| 순서 | 검토자 | 있는지 확인 | 부르는 법 |
|---|---|---|---|
| 1 | Codex | `codex --version` | `codex exec -s read-only "<검토 요청>"` · supervisor-worker 워크플로우면 [[codex-delegate]] |
| 2 | Grok | `omc ask grok -p "ping"` 이 답하는지 | `omc ask grok -p "<검토 요청>"` |
| 3 | Gemini | `gemini --version` | `omc ask gemini -p "<검토 요청>"` 또는 `gemini -p "<검토 요청>"` |
| 4 | Fable | Claude Code 의 Agent 도구 | Agent 도구에 `model: "fable"` 을 주고 검토만 맡긴다 |

- 앞 순서가 없거나 실패하면 다음으로 간다. **무엇을 썼는지, 왜 건너뛰었는지 보고에 적는다.**
- 작성자가 Fable 이면 4번은 자기 검토가 된다. 그때는 사용자에게 알리고 판단을 받는다.
- 검토 요청에는 원본 양식 경로와 산출물 경로, 확인할 것(내용 오류·양식 이탈·문장 티)을 적는다.
- 검토 결과는 그대로 믿지 않는다. 지적마다 맞는지 확인하고 반영한다.

### 2. 파일 형식을 양식과 맞춘다

- 양식 원본 파일을 바탕으로 다시 담는다. 슬라이드·용지 크기, 테마·마스터, 글꼴, 확장자를 양식과 같게 한다.
- 라이브러리의 기본 틀(`Presentation()`, `Document()`, `Workbook()`)에서 시작한 파일을 그대로 내지 않는다.
  기본 틀은 테마·마스터·크기가 양식과 다르고, 메타데이터에 흔적이 박혀 있다.
- 바꾼 뒤에는 실제 프로그램(PowerPoint·Word·Excel)으로 열어 그림으로 확인한다.

### 3. 메타데이터를 확인한다

```bash
python scripts/office_meta.py check <산출물> --template <양식>
```

보는 것: `docProps/core.xml` 의 작성자 · 마지막 수정자 · 만든 날짜 · 수정 날짜 · 설명,
`docProps/app.xml` 의 응용 프로그램 · 버전 · 문서 형식, 실제 슬라이드 비율.

| 표시 | 뜻 |
|---|---|
| 🔴 | 생성 라이브러리 문구 · 라이브러리 저자 · AI 이름 · 기본 틀 날짜가 그대로 있다 |
| 🟡 | 사람이 저장한 파일로 보기 어렵다 (비어 있음, 날짜 역전, 비율·응용 프로그램이 양식과 다름) |
| 🟢 | 흔적 없음 |

**양식도 함께 검사한다.** 양식 자체에 흔적이 있을 수 있다.

### 4. AI 흔적이 있으면 최종 수정한다

```bash
python scripts/office_meta.py fix <산출물> --template <양식> -o <새 파일> --author "<작성자>"
```

- 양식의 메타데이터를 따르되, 흔적이 있는 칸은 따르지 않는다.
  만든 날짜는 양식 값, 수정 날짜는 지금, 수정 번호는 양식 값 +1 이다.
- **작성자는 지어내지 않는다.** 양식 작성자가 쓸 수 없는 값이면 스크립트가 멈추고 `--author` 를 요구한다.
  그 이름은 사용자에게 받는다.
- 원본에 덮어쓰지 않는다. 새 파일로 쓰고, 스크립트가 쓴 직후 다시 검사한다.
- 본문 문장은 [[plain-writing]] 의 검사 스크립트로 따로 본다. 이 스크립트는 파일 속성만 본다.
- [[ai-trace-audit]] 이 설치돼 있으면 마지막에 한 번 더 돌린다. 저장 흔적과 대화 기록까지 대조한다.

**🟢 이 나와야 완료로 센다.** 고친 파일은 실제 프로그램으로 한 번 더 연다.

## 하지 않는 것

- 작성자 이름·날짜를 사용자 확인 없이 만들어 넣지 않는다.
- `.hwp` · `.hwpx` · `.pdf` 는 이 스크립트가 다루지 않는다. 지원하지 않는다고 보고한다.
- 검토 단계를 건너뛰고 메타데이터만 고치지 않는다. 겉만 바꾸는 것이 이 스킬의 목적이 아니다.

## 스크립트

| 파일 | 하는 일 |
|---|---|
| `scripts/office_meta.py check` | 흔적 검사. 흔적이 있으면 종료 코드 1 |
| `scripts/office_meta.py fix` | 양식 메타데이터를 따라 새 파일로 쓰고 다시 검사 |

표준 라이브러리만 쓴다. `setup.sh` / `setup.ps1` 은 파이썬 3.9+ 인지만 확인한다.
XML 은 파서로 다시 쓰지 않고 요소의 글자만 바꾼다 — ElementTree 로 왕복하면 네임스페이스
접두어가 바뀌어 Office 가 파일을 거부할 수 있다.

라이브러리 기본값은 2026-10-02 에 실측했다: python-pptx 1.0.2, python-docx, openpyxl 3.1.5, XlsxWriter.

## 이력 (필수 기록)

- 생성일: 2026-10-02
- 업데이트 횟수: 0
- 사용 이력
  - 2026-10-02 · 사용자가 마감 절차를 정했다. "외부 검토 → 양식 형식 → 메타데이터 → AI 흔적이
    있으면 최종 수정". 검토자는 Codex 가 없으면 Grok, Gemini, Fable 순.
    python-pptx 로 만든 초안에서 위 흔적이 나왔고, 받은 양식의 작성자가 `OpenAI` 인 것도 나왔다.
    그래서 fix 가 양식 값을 무조건 따르지 않고 흔적 칸은 사용자에게 받게 했다.
    시험: pptx 를 고친 뒤 PowerPoint 로 열어 그림으로 확인, xlsx·docx 는 Excel·Word 로 열림 확인.
