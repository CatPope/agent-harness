# 다른 엔진에서 달라지는 것

절차(용량 → 질의 유형 → 물리 설계 → 반정규화 → 실측)는 같다. 달라지는 것은 저장 구조와 운영이다.
출처는 2026-09-30 에 원문으로 확인했다.

## PostgreSQL

| 항목 | 내용 | 설계에 주는 뜻 |
|---|---|---|
| 페이지 | 표와 색인은 고정 크기 페이지 배열. 보통 8 kB (https://www.postgresql.org/docs/current/storage-page-layout.html) | 행 크기 계산의 단위 |
| 갱신 | 갱신하면 새 행 판이 생긴다. 옛 판은 VACUUM 이 회수한다. VACUUM 은 공간 회수, 통계, 가시성 맵, 트랜잭션 번호 되돌림 방지 때문에 필요하다 (https://www.postgresql.org/docs/current/routine-vacuuming.html) | 자주 갱신하는 표는 부푼다. autovacuum 을 끄지 않는다. 폴링마다 갱신하는 열(`last_seen_at`)은 이 비용을 낸다 |
| HOT | 색인이 걸린 열을 바꾸지 않고, 같은 페이지에 빈 공간이 있으면 색인 항목을 새로 만들지 않는다 (https://www.postgresql.org/docs/current/storage-hot.html) | 자주 바꾸는 열에는 색인을 걸지 않는다. 필요하면 fillfactor 로 페이지에 여유를 둔다 |
| BRIN | 물리 위치와 상관된 열이 있는 아주 큰 표용 블록 범위 색인 (https://www.postgresql.org/docs/current/brin.html) | 시간순으로만 쌓이는 로그 표의 시각 열 |
| pg_trgm | 낱말 앞에 공백 둘, 뒤에 하나를 붙여 trigram 을 뽑는다. 뽑을 trigram 이 없는 LIKE 패턴은 색인 전체 훑기가 된다 (https://www.postgresql.org/docs/current/pgtrgm.html) | 한국어 2글자 부분 일치에 약하다 |
| pg_bigm | 2-gram 색인 모듈 (https://github.com/pgbigm/pg_bigm) | 한국어·일본어처럼 짧은 낱말이 많은 언어 |
| 연결 | 연결마다 서버 프로세스 | 웹 서버에서는 연결 풀을 둔다 |

## MySQL (InnoDB)

(https://dev.mysql.com/doc/refman/8.4/en/innodb-index-types.html)

- 표 자체가 PK 로 정렬된 클러스터드 색인이다.
- 보조 색인 항목에는 PK 열이 들어간다. **PK 가 길면 보조 색인이 모두 커진다.** 짧은 PK 가 유리하다.
- 무작위 PK(UUIDv4)는 중간 삽입으로 페이지를 쪼갠다. 시간순 키(자동 증가, UUIDv7)가 낫다.

## Elasticsearch

- 한국어는 nori 분석기(mecab-ko-dic 사전으로 형태소 분석)를 쓴다
  (https://www.elastic.co/guide/en/elasticsearch/plugins/current/analysis-nori.html).
- 검색 엔진을 따로 두면 DB 와 색인 사이의 동기화 경로가 하나 더 생긴다. 규모가 요구할 때만 둔다.

## 언제 SQLite 를 떠나는가

SQLite 공식 기준(https://www.sqlite.org/whentouse.html)

- 하루 10만 요청 미만 웹사이트는 문제없다(보수적 추정, 10배 사례도 있다)
- 쓰기가 아주 많거나, 서버가 여러 대라 같은 DB 를 네트워크로 나눠 써야 하면 클라이언트/서버 DB
- DB 최대 281 TB, 파일시스템의 파일 크기 한도가 먼저 걸릴 수 있다
