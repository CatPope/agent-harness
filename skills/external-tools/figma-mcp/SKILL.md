# Figma MCP

## 이 스킬의 범위 — Figma 문서를 베끼지 않는다

**Figma 는 자기 사용법을 MCP 리소스로 직접 제공한다.** 도구별 사용법·API·문법은 그쪽이 정본이고,
버전이 올라가면 자동으로 갱신된다. **여기 옮겨 적으면 반드시 어긋난다.**

```
도구 목록·파라미터   file://figma/docs/tools-and-prompts.md
한도·권한            file://figma/docs/rate-limits-access.md
도구별 작성 지침      skill://figma/<스킬명>/SKILL.md
```

이 스킬에 남기는 것은 **저기에 없는 것** 셋뿐이다 — ① 호출 전 규약 ② 우리가 직접 겪은 함정
③ 결과를 믿지 않고 확인하는 법.

## 0. 착수 전 — 이 순서를 건너뛰지 않는다

```
1) whoami          tier · seat · planKey 확인 (한도 제외 도구라 공짜다)
2) 지침 선로드      §1 표대로. 서버가 강제한다
3) 작업
4) 눈으로 확인      §4. 🔴 API 응답은 증거가 아니다
```

🔴 **역할 구분 — 이 스킬은 관리자와 실행자(Codex)가 같이 읽는다.**
```
읽기        둘 다 한다
Figma 에 쓰기   관리자는 자유. 실행자는 지시서에 명시됐을 때만.
            실행자는 스스로 판단해 Figma 에 만들지 않는다 —
            외부 산출물이고 되돌리기가 로컬 파일보다 어렵다
한도        둘이 공유한다. 탐색하듯 훑지 않는다
```

`planKey` 는 **`whoami` 가 준 값을 그대로** 쓴다(`team::…` / `organization::…`).
기억해서 적지 않는다. 플랜이 여러 개면 어느 쪽인지 **사용자에게 묻는다.**

## 1. 🔴 지침 선로드 — 서버 측 강제 조건이다

아래 도구는 지침을 먼저 읽지 않으면 **"흔하고 디버깅하기 어려운 실패"**를 낸다(Figma 측 표현).

| 부르려는 도구 | 먼저 읽을 것 |
|---|---|
| `use_figma` | `skill://figma/figma-use/SKILL.md` |
| `get_design_context` | `skill://figma/figma-design-to-code/SKILL.md` |
| `generate_diagram` | `skill://figma/figma-generate-diagram/SKILL.md` + 해당 타입 `references/*.md` |
| `create_new_file` | `skill://figma/figma-create-new-file/SKILL.md` |
| `create_shader` · `create_generative_plugin` | 각 `figma-shaders` · `figma-generative-plugins` |

- FigJam·Slides 작업이면 `figma-use-figjam` · `figma-use-slides` 를 **같이** 읽는다.
- 읽은 뒤 호출할 때 `skillNames` 에 이름을 넘긴다. **MCP 리소스로 읽었으면 `resource:` 접두사**
  (예: `resource:figma-use`). 로깅용이라 실행에는 영향이 없지만 규약이다.

## 2. 언제 쓰고 언제 안 쓰나

```
✅ FigJam 도식          파이프라인·플로차트·시퀀스·ERD·간트 → generate_diagram
✅ 디자인 → 코드         figma.com URL 을 받았을 때 → get_design_context
✅ 도식을 파일로          문서에 넣을 SVG/PNG → download_assets
❌ Mermaid 문법만 필요   → mermaid-diagrams 스킬. Figma 를 거칠 이유가 없다
❌ 표로 충분한 것        도식은 관계가 있을 때 값이 난다. 단계 나열은 표가 낫다
❌ Weave · 셰이더 · 생성 플러그인   §5
```

## 3. 도식 만들기 — 주 용도

```
1) 근거 확보     코드·문서·회의록에서 실제 단계를 읽는다
                 🔴 없는 단계를 지어내 "채우지" 않는다. 빈 곳은 빈 채로 두고 말한다
2) generate_diagram   방향은 §4 를 보고 정한다
3) get_figjam         노드·커넥터·라벨이 의도대로인지 구조 확인
4) get_screenshot     🔴 눈으로 본다
5) download_assets    SVG 로 추출
```

- **고쳐 만들 때는 `fileKey` 를 넘긴다.** 안 넘기면 호출마다 드래프트에 새 파일이 생긴다.
- `create_new_file` 을 먼저 부르지 않는다 — `generate_diagram` 이 스스로 만든다.
- 두 번 고쳐서 안 되면 세 번째를 시도하지 말고 **무엇이 마음에 안 드는지 묻는다.**

## 4. 🔴 실측으로 확인된 함정 (2026-09-16)

| 함정 | 증상 | 대응 |
|---|---|---|
| **`upload_assets` 기본 `scaleMode: FILL`** | 타깃 노드를 안 주면 새 프레임을 만드는데 **그 비율이 이미지와 달라 잘린다.** 응답은 `success: true` | `scaleMode: "FIT"` 또는 프레임을 원본 비율로 리사이즈 |
| **업로드 파일명 인코딩** | multipart `filename` 의 한글이 latin-1 로 읽혀 레이어명이 깨진다 (`검사…` → `°Ë»ç…`) | **파일명은 ASCII로 올리고, 이름은 뒤에 `use_figma` 로 붙인다** |
| **`flowchart LR` 의 가로 폭** | 단계가 늘면 극단적으로 길어진다(실측 3964×418, 9.5:1). 문서에 넣으면 글자를 못 읽는다 | 단계가 6개 넘으면 `TD` 로 하거나 쪼갠다 |
| **SVG 텍스트가 파일 종류마다 다르다** | Design(`/design/`)은 `<text>` 유지, **FigJam(`/board/`)은 전부 `<path>` 아웃라인** | FigJam 도식은 오타를 SVG 에서 못 고친다 — 다시 생성한다 |
| **`get_metadata` 페이지 목록이 일부만 나온다** (2026-09-28) | nodeId 없이 부르면 불러온 페이지만 나온다. 실측: 77페이지 파일에서 `Thumbnail` 1개만 나옴 | 페이지 수는 `use_figma` 읽기 전용 스크립트 `figma.root.children` 로 센다. 1개만 나오면 의심한다 |
| **`search_design_system` 이 빈 결과** (2026-09-28) | 발행된 라이브러리만 찾는다. 커뮤니티 파일 복제본 안의 부품은 안 나온다. 한 번에 쿼리 1개로 잘린다 | 파일 안 부품은 페이지 목록·스크린샷으로 확인한다 |
| `get_variable_defs` 가 `{}` | 변수를 안 쓴 파일이면 정상이다 | 실패로 보고하지 않는다 |
| 드래프트 난립 | `generate_diagram` 이 호출마다 파일 생성 | `fileKey` 재사용. **MCP 에 삭제 도구가 없다** — 정리는 사용자 몫이라고 알린다 |
| **변수에 묶인 칠을 복사하면 색이 안 바뀐다** (2026-11-17) | 다른 인스턴스의 `fills` 를 통째로 복사했더니 칠 안의 `boundVariables` 까지 따라와 원래 변수 색으로 되돌아갔다. 응답은 오류 없음 | 색만 바꿀 때는 `{type:'SOLID', color}` 새 칠을 넣고, 넣은 뒤 칠의 `boundVariables` 가 비었는지 본다 |
| **휴대폰 화면이 발표 모드에서 스크롤되지 않는다** (2026-11-17) | 내용 프레임이 화면(844)보다 길어도 `overflowDirection` 이 `NONE` 이면 하단 탭 뒤로 잘린 채 멈춘다. 사용자가 발표 모드에서 처음 알아챘다 | 내용 프레임 높이를 하단 막대 위까지 FIXED 로 두고 `clipsContent = true`, `overflowDirection = 'VERTICAL'`. 길게 그린 최상위 프레임은 발표 '맞춤' 배율에서 작게 줄어드니 844 로 줄이고 같은 방식으로 |
| **인스턴스 안 노드의 순서·크기는 못 바꾼다** (2026-11-17) | 컴포넌트에 박힌 막대 조각(위치·폭)은 인스턴스에서 옮기거나 늘릴 수 없다 | 보이기/숨기기와 칠·선 덮어쓰기로 맞추거나, 데이터 쪽을 컴포넌트 모양에 맞춘다. 목록 줄 순서는 오토레이아웃 부모가 인스턴스가 아닐 때만 `insertChild` 로 바꾼다 |

## 4-1. 덱 파일에서 틀 고르기 (2026-10-15)

장이 수십 장인 커뮤니티 덱을 읽을 때 장마다 부르지 않는다. 읽기 한도를 아끼고 빨리 고른다.

```
1) get_metadata(페이지 id)   결과가 커서 파일로 저장된다. JSON 의 text 를 이어 붙이고 마지막 </canvas> 뒤를 잘라 XML 로 읽는다.
                             최상위 frame 의 이름, id, x, y 를 뽑는다
2) get_screenshot(페이지 id, maxDimension 6000)   한 번만 부른다. 페이지 원점(최소 x, y)과 배율로 장마다 잘라
                             번호를 붙인 모아 보기 그림을 만든다. 60장을 한 번에 본다
                             → scripts/deck_contact.py <metadata 파일> <스크린샷> <출력 폴더>
3) 고른 틀만 get_design_context   글꼴, 색, 칸 위치를 얻는다. 그림 자산 URL 은 7일 뒤 끊기니 바로 받는다
```

- 링크의 node-id 가 가리키는 것이 장이 아니라 표지 페이지(canvas)일 수 있다. metadata 로 먼저 확인한다.
- 칸이 많은 장(노드 180개 넘음)은 get_design_context 가 25,000 토큰에서 잘린다. 같은 꼴이 되풀이되는 장이면 잘린 앞부분으로 충분하다.
- 틀 글꼴이 유료이거나 한글이 없으면 그대로 못 쓴다. 바꿀 글꼴은 사용자에게 묻는다.

## 4-2. 화면 묶음의 흐름 검토와 프로토타입 (2026-11-17)

여러 세션이 나눠 그린 화면 수십 장을 이어 볼 때 쓴다. 화면 하나하나보다 화면 사이의 데이터와 이동을 본다.

```
1) 화면 목록      get_metadata(페이지) 를 파일로 받아 섹션별 최상위 frame 의 id·이름·위치를 뽑는다
2) 눈으로 보기    섹션마다 get_screenshot(maxDimension 6000) 한 번. 여백(40)을 빼고 화면 단위로 잘라 4장씩 모아 본다
3) 글자 덤프      use_figma 읽기 스크립트로 화면마다 TEXT 의 id 와 글자를 뽑는다(섹션별 병렬 호출)
4) 대조          날짜·시각·사람·상태·수량·용어가 화면마다 같은지 본다. 기준 시각이 없으면 먼저 정한다
5) 시나리오 표    기준 시각, 사람과 역할, 회차 상태, 공지·자료 목록을 md 하나로 정하고 모든 화면을 거기에 맞춘다
6) 고치기        글자(일괄 치환 + id 별 수정) → 컴포넌트 속성 → 숨김·순서 → 모양 덮어쓰기 순. 매번 고친 수와 못 찾은 id 를 돌려받는다
7) 연결          뒤로 버튼은 BACK, 하단 탭·왼쪽 메뉴는 공통 규칙, 나머지는 [화면, 글자, 목적지] 표로 건다
8) 시작 지점      page.flowStartingPoints 에 흐름마다 하나
9) 확인          reactions 를 다시 읽어 화면별 들어오는·나가는 연결 수를 센다. 들어오는 연결 없는 화면은 상태 화면인지 빠진 흐름인지 가른다
10) 스크롤        내용이 화면보다 긴 곳을 재서 §4 스크롤 함정대로 고친다. 발표 모드에서 사람이 처음 알아채는 문제다
```

- 글자에서 누를 대상을 찾을 때는 가장 가까운 인스턴스를 고른다. 나눔 고르기처럼 칸 둘이 한 인스턴스에 있으면 글자의 부모 프레임을 고른다.
- 숨긴 줄 안의 글자는 찾지 않는다(조상의 `visible` 을 본다).
- 기기 틀(iPhone 등)은 Plugin API 로 정할 수 없다. 사용자가 Prototype 패널에서 고른다고 알린다.

## 5. 🔴 결과를 눈으로 확인한다 — 응답은 증거가 아니다

`success: true` 를 받고도 **이미지가 잘려 있었고 레이어 이름이 깨져 있었다**(2026-09-16 실제 사례).
읽기 도구도 마찬가지다 — 한 섹션만 보고 "도식 정상"이라고 보고했다가 전체를 안 봤던 적이 있다.

```
쓰기 후   use_figma 안에서 await node.screenshot()  ← 별도 호출 없이 인라인으로 본다
구조      get_metadata · get_figjam 으로 이름·개수·계층 대조
전체      get_screenshot 은 반드시 전체 노드로 한 번. 부분만 보고 판단하지 않는다
파일      저장한 SVG 는 로컬에서 실제로 렌더해 본다 (아래)
```

**저장한 SVG 를 로컬에서 렌더하는 법** — 뷰포트에 잘리지 않게 HTML 로 감싼다.

```bash
cat > view.html <<'EOF'
<!doctype html><body style="margin:0;background:#fff">
<img src="diagram.svg" style="width:1400px;display:block"></body>
EOF
"$EDGE" --headless --disable-gpu --hide-scrollbars --window-size=1400,150 \
        --screenshot=out.png "file:///$(cygpath -m "$PWD/view.html")"
```
`$EDGE` 는 설치된 Edge·Chrome 실행 파일. **SVG 를 직접 열면 창 크기만큼만 잘려 나온다** —
그래서 `<img style="width:…">` 로 감싼다.

## 7. 한도 — 착수 전에 `whoami` 로 본다

한도는 **플랜**이 정한다(시트가 아니다). 정확한 값은 `file://figma/docs/rate-limits-access.md`.

- **읽기 도구만** 한도를 깎는다. `whoami` · `create_new_file` · `add_code_connect_map` 은 제외.
- Starter 는 시트와 무관하게 월 단위 소량이다 — **시트만 올려도 안 풀린다. 플랜을 봐야 한다.**
- 접근 범위는 **그 계정이 이미 볼 수 있는 파일**뿐이다. 다른 조직의 파일은 계정을 바꿔야 한다.
- 🔴 계정·플랜 변경은 **사용자가 직접** 한다. 가입·신청·결제는 대신하지 않는다.
