# 커서 시연 리허설

에이전트가 사람 대신 마우스와 키보드를 잡고, 커서 옆 말풍선으로 설명하며 프로그램을 돌린다.
발표에서는 그대로 시연이 되고, 발표 전에는 같은 것이 리허설(통합 시험)이 된다.

| | 이 스킬 | [[background-ui-test]] |
|---|---|---|
| 화면 | **사람이 보는 화면을 잡는다** | 사람 화면을 건드리지 않는다 |
| 언제 | 사람이 요청했거나 합의했을 때만 | 사람이 일하는 동안 언제든 |
| 목적 | 보여 주기 + 끝에서 끝까지 확인 | 조용한 기능 시험 |

시연 준비 단계(로그인, 창 배치, 상태 확인)는 [[background-ui-test]] 규칙을 따른다. 커서를 잡는 것은 실행하는 동안뿐이다.

## 1. 구성

```
커서 시연 도구     말풍선 창 + 입력 보내기 + 요소 찾기. 아래 「도구가 할 줄 알아야 하는 것」
장면 파일          장면 하나 = JSON 배열 하나. 한 줄에 한 단계
실행기             장면을 차례로 돌리고 장면별 시간을 찍는다. 「장면:행」 으로 중간부터 잇는다
대본 생성기        장면 파일 → 대본 엑셀(scripts/scenes_to_xlsx.py)
```

### 도구가 할 줄 알아야 하는 것

| 단계 | 하는 일 |
|---|---|
| `front` | 창을 복원해 앞으로. 이미 맨 앞이면 아무 키도 보내지 않는다(§6 함정) |
| `point` | 대상을 찾아 커서를 사람처럼 옮기고 말풍선을 띄운 채 읽을 시간만큼 머문다 |
| `click` `dclick` `rclick` | 지금 커서 자리를 누른다 |
| `type` | 글자를 친다. 원격 화면 안이면 가상 키 + 스캔 코드로 |
| `key` | 조합 키(`ctrl+a`, `enter`) |
| `waitfor` | 대상이 나타날 때까지 짧은 간격으로 다시 찾는다. 시간을 넘기면 오류로 멈춘다 |
| `read` | 화면 글자를 읽어 변수에 담는다(예: 연결 코드). 뒤 단계에서 `{변수}` 로 쓴다 |
| `say` | 커서를 안 옮기고 말풍선만 |
| `space` | 원격 화면 좌표계를 정한다(원점, 배율). 뒤의 `"in": "<이름>"` 단계가 그것으로 바꾼다 |
| `move` `scroll` `wait` `hide` | 옮기기, 굴리기, 기다리기, 말풍선 숨기기 |

말풍선 창은 **포커스를 받지 않고 클릭이 통과해야 한다**(Windows 는 `WS_EX_NOACTIVATE | WS_EX_TRANSPARENT | WS_EX_LAYERED | WS_EX_TOPMOST`).
그래야 말풍선이 떠 있어도 밑의 프로그램을 누를 수 있다.

## 2. 장면 파일 규칙

```json
[
  {"op": "front", "win": "<웹 창 제목>", "after": 0.4},
  {"op": "point", "win": "<웹 창 제목>", "name": "새 PC 등록", "text": "「새 PC 등록」에서 연결 코드를 받습니다."},
  {"op": "click", "after": 0.8},
  {"op": "waitfor", "win": "<에이전트 창 제목>", "name": "연결됨", "timeout": 20},
  {"op": "point", "in": "remote", "x": 573, "y": 459, "text": "원격 PC 에이전트입니다."}
]
```

- **한 줄에 한 단계.** 행 번호가 곧 단계 위치라, 멈춘 행부터 `A:63` 처럼 이어 돌릴 수 있다.
- **대상은 이름으로 찾는다.** 좌표는 이름을 읽을 수 없는 곳(원격 화면 안, 작업 표시줄 아이콘)에만 쓴다.
  이름으로 찾으면 창이 옮겨지거나 배치가 바뀌어도 따라간다.
- **결과는 `waitfor` 로 기다린다.** 「몇 초 쉬기」 로 맞추지 않는다. 늦게 뜨면 기다리고 빨리 뜨면 바로 넘어간다.
- **말풍선 시간 = 0.5초 + 공백 뺀 글자 수 ÷ 10.** 처음엔 1.6초 + ÷7 이었는데 사람이 늘어진다고 했다.
  단추 이름만 띄우는 짧은 말풍선(「저장」, 「연결」)은 0.5~0.8초로 따로 준다.
- **입력은 커서를 그 칸에 대고 설명한 뒤 친다.** 보는 사람의 시선을 먼저 데려간다.
- **멘트는 실제 결과를 확인할 수 없는 곳이면 단정하지 않는다.** AI 답, 개수 같은 것은 미리 써 둔 멘트와 실제가 어긋날 수 있다(§5-5).

## 3. 화면이 바뀌어도 따라가는 까닭과 멈추는 까닭

- 매 단계 직전에 UI Automation 으로 그 창의 요소 목록을 다시 읽어 이름이 같은 것의 위치를 받는다.
- `waitfor` 는 0.5초마다 다시 찾는다. 집 PC 가 30초 뒤에 받든 10초 뒤에 받든 뜨는 순간 넘어간다.
- **찾는 것이 없거나 시간을 넘기면 그 자리에서 오류를 내고 멈춘다**(빠른 실패). 엉뚱한 곳을 누르며 이어 가지 않는다.
  오류에는 창, 이름, 후보 수를 남긴다. 사람에게 설명할 때 이 두 가지를 말해 준다.

## 4. 원격 PC 를 함께 쓰는 시연

원격 데스크톱 창 안쪽은 요소 이름을 읽을 수 없다. 원격 화면 좌표를 이쪽 화면 좌표로 바꿔 가리킨다.

```
이쪽 x = 원점 x + 원격 x × 배율
이쪽 y = 원점 y + 원격 y × 배율
```

- 원점과 배율은 원격 창을 캡처해 원격 화면의 좌우 끝과 작업 표시줄 아래 끝으로 잰다. 원격 창 크기가 바뀌면 다시 잰다.
- 원격 PC 의 창 배치를 **고정하고 겹치지 않게** 둔다. 좌표 시연이라 배치가 바뀌면 따라가지 못한다.
- 원격 PC 에 세션이 따로 있으면 메시지로 나눠 맡는다: 창 배치와 줄 위치 재기(목록 첫 줄 y, 한 줄 높이), 시연 뒤 실제 결과 확인.
  상대 세션이 권한 판단으로 거부한 일(서명 없는 설치 등)을 돌아가지 않는다. 사람이 그쪽에 직접 승인한다.
- 원격 화면 안 키 입력은 스캔 코드가 있어야 넘어간다(§6).

## 5. 리허설 절차

### 5-1. 준비 (커서를 잡지 않는다)

- 시연에 필요한 프로그램만 띄운다. 예전 방식의 보조 터미널, DB 도구는 띄우지 않는다.
- 다른 창은 **최소화한다. 닫지 않는다**(사람의 작업이다).
- 받는 폴더 같은 결과 자리는 비워 둔다. 남은 파일은 **지우지 말고 옮긴다.** 같은 이름이 있으면 `(1)` 이 붙어 줄 위치도 바뀐다.
- 목록은 보기 방식과 정렬을 고정한다(자세히, 이름 오름차순). 줄 좌표가 그것에 달려 있다.
- 로그인(OAuth) 화면은 오래 열어 두지 않는다. 만료되면 「로그인 시간이 지났습니다」로 돌아온다. 계정 선택부터 끝까지 한 번에 간다.
  동의 화면을 에이전트가 눌러도 되는지는 그 시험마다 사람에게 받는다.
- 앱이 제목을 스스로 바꾸는지 본다(예: AI 터미널은 대화 주제로 제목이 바뀐다). 장면이 창을 제목으로 찾는다.

### 5-2. 허락 받기

사람이 다른 일을 하고 있을 수 있다. 알림(토스트)으로 「시작해도 될까요? 약 N분 마우스·키보드를 잡습니다」를 묻고 답을 받은 뒤 돈다.

### 5-3. 실행

- 실행기를 백그라운드로 돌리고 끝 알림을 기다린다. 장면별 걸린 시간을 찍는다.
- 리허설 중 단계마다 사람이(에이전트가) 화면을 읽고 다음 조각을 쓰면 몇 배 느려진다. 장면 파일 하나를 쉬지 않고 돈다.

### 5-4. 멈췄을 때

1. 오류 줄에서 장면, 창, 이름을 본다.
2. 그 창의 요소 목록을 다시 덤프하고(걸린 시간도 잰다) 화면을 캡처한다. 목록과 화면이 다르면 도구 쪽 문제다.
3. 한 단계씩 나눠 재현해 어느 단계 뒤에 깨지는지 가린다(§6 의 두 함정을 이렇게 찾았다).
4. 장면 파일만 고치지 말고 **도구를 고친다.** 같은 문제가 다른 장면에서 또 난다.
5. 앞에서 끝난 일(연결, 업로드)은 그대로 두고 멈춘 행부터 잇는다.

### 5-5. 끝났을 때 — 도구가 끝까지 간 것은 성공이 아니다

- 실제 데이터로 확인한다: 서버 기록(작업 상태, 시각), 받는 PC 의 파일(이름, 크기, `(1)` 유무), 웹 화면.
- 미리 써 둔 멘트와 실제 결과를 대조한다(예: 「두 방에 붙였습니다」 ↔ 웹에 보이는 태그 수).
- 캡처는 화면 갱신 직전일 수 있다. 다르게 보이면 한 번 더 본다.
- 사람이 화면을 다시 쓰기 시작한 흔적(다른 페이지로 바뀜)이 보이면 창을 앞으로 가져오지 않는다.

## 6. 함정

| 증상 | 원인 | 처방 |
|---|---|---|
| 최소화했던 WebView2 앱 창을 띄웠는데 요소를 못 찾음 | UIA 좌표가 최소화 때 값(x 32000 근처)에 머묾. 창을 옮겨도 그대로 | 되살린 뒤 창 크기를 2px 바꿨다 되돌린다 |
| 이미 앞에 있는 창의 요소를 찾다 60초 넘게 멈춤 | 창을 앞으로 가져오려고 보낸 Alt 가 그 창에 들어가 메뉴 모드가 켜지고 화면 스레드가 묶임 | 이미 맨 앞이면 Alt 를 보내지 않는다. 걸렸으면 Esc |
| 원격 데스크톱 창 안에 글자가 안 들어감 | 가상 키만 보냄, 유니코드 입력도 안 넘어감 | 가상 키 + 스캔 코드. 숫자·영문은 키로, 한글은 상대 PC 에서 |
| 원격 창을 처음 누르면 반응이 없음 | 첫 클릭은 창 활성화에 쓰임 | 두 번 누른다 |
| 이름에 `[ ]` 든 요소를 못 찾음 | PowerShell `-like` 와일드카드 | `.Contains()` 비교 |
| 「닫기」를 눌렀더니 다른 창이 닫힘 | 같은 이름 첫 요소가 창 제목줄 닫기 | 창 기준 상대 좌표로 누르거나 상위 요소로 좁힌다 |
| 목록 밖에서 굴렸더니 안 내려감 | 굴리기는 커서 아래 요소에 감 | 목록 위로 옮긴 뒤 굴린다 |
| UIA 질의 스크립트가 깨짐 | 표준 입력으로 넘긴 스크립트의 블록이 갈라짐 | `-EncodedCommand`(UTF-16LE base64)로 넘긴다 |
| 원격 PC 에이전트를 다시 켰더니 창이 다른 곳에 뜸 | 앱 기본 위치 | 장면에서 그 뒤 좌표가 필요하면 그 위치 기준으로 잰다 |
| 리허설 뒤 브라우저가 최대화돼 다른 창을 덮음 | 확인 중(원인 미상) | 장면 첫 단계에 창 배치(`place`)를 둔다 |

## 7. 대본 엑셀

클릭 단위만 나열하면 사람이 읽지 못한다. **장면 → 동작 → 클릭** 3단으로 만든다.

| 시트 | 내용 |
|---|---|
| 흐름 | 동작 한 줄씩(20개 안팎): 장면, 동작, 번호 범위, 보여 주는 것, 화면, 말풍선 초 합 |
| 대본 | 클릭 한 줄씩: 장면, 동작, 번호, 화면(어느 PC 의 어느 창·화면), 설명(커서가 하는 일), 멘트, 말풍선 초. 장면·동작·화면 열을 병합, 동작 사이 가는 선, 장면 사이 굵은 선 |
| 리허설 결과 | 회차, 시각, 걸린 시간, 무엇이 있었나, 고친 것·남은 것 |

```
python scripts/scenes_to_xlsx.py <설정.json>
```

- 설정 파일에 장면 폴더, 장면 제목, 창 제목 → 화면 이름, 이름 없는 좌표 지점, 동작 묶음(첫 줄 번호 → 이름, 보여 주는 것), 리허설 결과를 둔다. 예시는 `scripts/example-config.json`.
- 장면 파일에서 줄이 늘거나 줄면 동작 묶음의 번호가 밀린다. 생성기가 이름 없는 동작을 알려 준다.
- 병합한 표는 정렬·필터를 걸지 않는다(줄이 어긋난다).
- 표를 손으로 고치지 말고 장면 파일을 고친 뒤 다시 뽑는다. 대본과 시연이 어긋나지 않는다.
- 엑셀이 열려 있으면 저장이 막힌다. 창에 닫기 신호만 보낸다(저장 안 된 변경이 있으면 Excel 이 묻는다).
- `openpyxl` 이 필요하다. 처음 한 번 `setup.ps1`(Windows) 또는 `setup.sh` 를 돌린다(`requirements.txt` 를 설치한다).
