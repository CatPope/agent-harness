# 백그라운드 UI 시험

사람과 에이전트가 **한 PC 를 나눠 쓰는** 시험이다. 사람은 다른 가상 데스크톱에서 자기 일을 하고,
에이전트는 시험 데스크톱에서 앱과 브라우저를 실제 사용자처럼 조작한다. 사람은 마지막에 직접 한 번 더 시험한다.

이 스킬이 막으려는 사고는 하나다. **에이전트의 조작이 사람의 키보드 입력을 가로채는 것.**
사람이 문서를 치다가 글자가 시험 창으로 넘어가면 그 순간 시험도 일도 망가진다.

## 1. 지킬 것

| 규칙 | 이유 |
|---|---|
| **포커스를 뺏지 않는다** | 사람이 치던 글자가 시험 창으로 들어간다. 실제로 매번 이렇게 끊겼다 |
| **시험 가상 데스크톱을 벗어나지 않는다** | 띄울 때도, 조작할 때도. 사람이 쓰는 데스크톱에 창이 뜨면 그 화면을 덮는다 |
| **사람이 쓰는 브라우저 창을 건드리지 않는다** | URL 을 그냥 열면 사람이 지금 쓰는 창에 탭이 뜬다. 시험용 프로필을 따로 띄운다(§4) |
| **실제 사용자처럼 클릭과 키 입력으로 한다** | 값을 DOM 에 바로 넣거나 API 를 부르면 실제 화면 흐름을 시험하지 못한다 |
| **사람 손이 필요하면 Windows 알림을 띄운다** | 사람은 다른 데스크톱에 있어 이 세션 화면을 보고 있지 않다(§7) |
| **대신 처리한 것은 적어 둔다** | 사람이 마지막에 직접 시험할 목록이 된다(§9) |
| **비밀번호와 계정 로그인은 사람이 한다** | 시험용 프로필에 한 번 저장해 두면 다음부터 에이전트는 계정만 고른다(§4) |

## 2. 준비

### 시험 데스크톱과 기준 창

시험 데스크톱은 **에이전트 세션이 도는 터미널 창이 있는 데스크톱**으로 정한다. 그 창이 기준 창이다.
스크립트는 기준 창을 `-RefHwnd <핸들>` 또는 `-RefProcess <프로세스 이름>` 으로 받는다.

```powershell
# 창마다 데스크톱 ID 와 "현재" 여부
scripts\vdesk.ps1
# 사람이 지금 시험 데스크톱에 있는가
scripts\vmove.ps1 -Check -RefProcess <터미널 프로세스>     # here / away
```

### 스크립트

모두 `scripts/` 에 있다. PowerShell 5.1 에서 돈다. **UTF-8 BOM 으로 저장돼 있다.** BOM 을 빼면
5.1 이 한글을 깨뜨려 파싱 오류가 난다. 고쳐 저장할 때도 BOM 을 유지한다.

| 스크립트 | 하는 일 | 포커스 |
|---|---|---|
| `cdp.ps1` | 브라우저 페이지에 마우스·키 이벤트, 파일 올리기, 페이지 캡처 | 안 뺏음 |
| `uia.ps1` | UI Automation 으로 요소 찾기·누르기·값 넣기 | **앱마다 다르다**(§3) |
| `dlgfill.ps1` | Windows 파일·폴더 선택 창에 경로 넣고 확인 | 안 뺏음 |
| `dlglist.ps1` | 대화상자 자식 컨트롤 목록. `dlgfill` 이 칸을 못 찾을 때 | - |
| `winshot.ps1` | 창 하나만 캡처. 다른 데스크톱에 있어도 찍힌다 | 안 뺏음 |
| `vdesk.ps1` | 창별 가상 데스크톱 | - |
| `vmove.ps1` | 창을 시험 데스크톱으로 옮기기, `-Check` | 안 뺏음 |
| `launch-when-here.ps1` | 사람이 시험 데스크톱에 오면 그때 앱을 켜고 켠 시각을 남김 | - |
| `notify.ps1` | Windows 토스트 알림. 안 되면 풍선 알림 | - |

## 3. 조작 방법 고르기

**대상마다 포커스를 뺏는지가 다르다.** 아래는 실측이다. 표에 없는 대상은 §10 리허설로 먼저 확인한다.

| 대상 | 쓰는 방법 | 실측 |
|---|---|---|
| 브라우저(Chrome) 페이지 | **CDP** `Input.dispatchMouseEvent` · `dispatchKeyEvent` · `insertText` | 창이 뒤에 있어도 동작. 포커스 안 뺏음 |
| Chrome 의 UIA Invoke | **쓰지 않는다** | 창을 앞으로 끌어온다. 사람이 치던 글이 넘어갔다 |
| WebView2 앱(pywebview 등) | UIA Invoke·SetValue | 포커스 안 뺏음. CDP 가 필요하면 아래처럼 띄운다 |
| Win32 공용 파일·폴더 선택 창 | `dlgfill.ps1` (WM_SETTEXT + PostMessage BM_CLICK) | 활성화 안 일어남 |
| 브라우저의 파일 선택 창 | `cdp.ps1 -Action upload` 로 가로채기 | 버튼은 실제로 누르고 창만 CDP 가 받는다 |
| `SetForegroundWindow` 같은 앞으로 가져오기 | **쓰지 않는다** | 막히면 작업 표시줄 단추가 주황색으로 깜박인다. 사람이 그걸 누르면 시험 창으로 포커스가 간다 |
| 탐색기·작업 관리자 | **열지 않는다** | 열리면서 앞으로 온다. 텍스트 증거로 대신한다(§6) |

### CDP 예시

```powershell
# 탭 목록
scripts\cdp.ps1 -Port 9224
# 보이는 글자로 찾아 누르기, 선택자 + 글자로 좁히기
scripts\cdp.ps1 -Port 9224 -Url <주소 일부> -Action click -Text "보내기"
scripts\cdp.ps1 -Port 9224 -Url <주소 일부> -Action click -Selector "button" -Text "전달"
# 칸을 누른 뒤 한 글자씩 치기(ASCII 는 keyDown/keyUp, 한글은 insertText 로 IME 확정처럼)
scripts\cdp.ps1 -Port 9224 -Action click -Selector "input[name=q]"
scripts\cdp.ps1 -Port 9224 -Action type -Text "검색어"
scripts\cdp.ps1 -Port 9224 -Action key -Text Enter
# 업로드 버튼을 실제로 누르고 파일 선택 창은 가로채 파일을 넣는다
scripts\cdp.ps1 -Port 9224 -Action upload -Text "파일 선택" -File <파일 경로>
# 페이지 캡처, 화면 글자
scripts\cdp.ps1 -Port 9224 -Action shot -File <png 경로>
scripts\cdp.ps1 -Port 9224 -Action text
```

`cdp.ps1` 은 연결할 때마다 `Emulation.setFocusEmulationEnabled` 를 켠다. 창이 뒤에 있어도 페이지는
포커스를 가진 것처럼 동작한다(`:focus`, focus 이벤트). 이것이 없으면 칸을 눌러도 입력이 안 들어가는 페이지가 있다.

### WebView2 앱에 CDP 붙이기

```powershell
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = "--remote-debugging-port=9223"
Start-Process <앱 실행 파일>       # 같은 셸에서 띄워야 환경 변수가 넘어간다
scripts\cdp.ps1 -Port 9223
```

### UIA 예시

```powershell
scripts\uia.ps1 -Hwnd <창 핸들> -Action dump
scripts\uia.ps1 -Hwnd <창 핸들> -Action invoke -Name "연결" -Type Button
scripts\uia.ps1 -Hwnd <창 핸들> -Action set -Type Edit -Index 0 -Value "<값>"
```

### 파일·폴더 선택 창

```powershell
scripts\dlgfill.ps1 -Hwnd <대화상자 핸들> -Path "<폴더 경로>"
```

- 이름 칸은 컨트롤 ID 1148(파일) 또는 1152(폴더) 아래 Edit 다. 폴더 선택 창에서는 1152 Edit 가
  `#32770` 바로 아래에 있었다. 못 찾으면 `dlglist.ps1` 로 구조를 본다.
- 다른 프로세스의 창이라 `GetWindowText` 로 다시 읽으면 빈 값이 나온다. **값은 들어가 있다.** 확인 뒤 결과 폴더로 판단한다.
- 확인 버튼(ID 1)은 `PostMessage` 로 누른다. `SendMessage` 는 대화상자가 닫힐 때까지 안 돌아올 수 있다.

## 4. 시험용 브라우저 프로필

사람이 쓰는 브라우저와 **프로필을 나눈다.** 그래야 사람 창에 탭이 뜨지 않고, CDP 도 붙는다.

```powershell
chrome.exe --user-data-dir="$env:LOCALAPPDATA\<시험 프로필 이름>" --remote-debugging-port=9224 `
  --no-first-run --no-default-browser-check --new-window <시작 주소>
```

- **Chrome 136 이상은 기본 프로필에 원격 디버깅을 막는다.** `--user-data-dir` 로 따로 만든 프로필이어야 포트가 열린다.
- 처음 한 번은 사람이 로그인하고 **계정을 프로필에 저장**한다. 다음부터 에이전트는 계정 선택 화면에서 계정만 누른다.
  에이전트는 비밀번호를 치지 않는다.
- 띄우는 것도 §5 규칙을 따른다. 사람이 다른 데스크톱에 있을 때 띄우면 그쪽에 뜬다.
- 창이 최소화되면 `winshot` 캡처가 빈 그림이 된다. 페이지 증거는 `cdp.ps1 -Action shot` 으로 찍는다.

## 5. 창 띄우기

**새 창은 사람이 있는 데스크톱에 뜬다.** 에이전트가 어디서 띄웠는지는 상관없다.

1. 사람이 시험 데스크톱에 있을 때만 띄운다. `vmove.ps1 -Check` 가 `here` 일 때.
2. 앱 켜는 시각이 시험 단계라면 `launch-when-here.ps1` 로 기다렸다 켠다. 켠 시각이 증거로 남는다.
   ```powershell
   scripts\launch-when-here.ps1 -Target "<시작 메뉴 바로 가기.lnk>" -RefProcess <터미널> -LogFile <증거 폴더>\켠시각.txt
   ```
   시작 메뉴 바로 가기를 쓰는 이유는 **사람이 실제로 켜는 경로**와 같게 하려는 것이다.
3. 그래도 다른 데스크톱에 떴으면 `vmove.ps1 -Hwnd <핸들> -RefProcess <터미널>` 로 옮긴다.
   - 옮기기는 Windows 10 19041~19045 의 내부 COM 인터페이스로 확인했다. Windows 11 은 내부 GUID 가 달라
     그대로는 안 된다(직접 확인하지 않았다). 옮기기가 실패하면 사람에게 알림으로 옮겨 달라고 한다.
4. **켜질 때 자기 창을 앞으로 가져오는 앱이 있다.** 그런 앱은 2번 방식으로만 켠다. 관찰 사항으로도 적는다.

## 6. 증거 남기기

| 무엇 | 방법 |
|---|---|
| 앱 창 | `winshot.ps1 -Hwnd <핸들> -OutDir <증거 폴더> -Name 03_전달대기.png` |
| 브라우저 페이지 | `cdp.ps1 -Action shot -File <증거 폴더>\03_웹.png` |
| 파일이 생겼는가 | `Get-ChildItem <폴더> \| Select Name,Length,CreationTime,LastWriteTime` 를 txt 로 |
| 내용이 같은가 | `certutil -hashfile <파일> SHA256` 을 txt 로 |
| 프로세스가 꺼졌는가 | `Get-Process <이름>` 결과(없음)와 시각을 txt 로 |
| 켠 시각 | `launch-when-here.ps1 -LogFile` |

- **화면 전체 캡처는 쓰지 않는다.** 사람이 일하는 데스크톱이 찍힌다.
- `winshot` 은 조건에 맞는 창이 여럿이면 가장 큰 창을 고른다. 엉뚱한 창이 찍힌 적이 있다. 핸들을 알면 `-Hwnd` 를 준다.
- 최소화된 창은 수백 바이트짜리 빈 그림이 나온다. 크기로 걸러 내고, 무효인 캡처는 무효라고 적는다.
- 탐색기·작업 관리자 화면 대신 txt 를 냈다면 그것도 §9 목록에 넣는다.

## 7. 알림과 중계

```powershell
scripts\notify.ps1 -Title "시험: 로그인 필요" -Body "시험 데스크톱의 브라우저에서 계정 로그인을 해 주세요."
```

이럴 때 띄운다.

- 로그인, 승인 창, 비밀번호, 연결 코드처럼 **사람만 할 수 있는 일**이 생겼다
- 사람이 시험 데스크톱으로 와야 다음 단계를 할 수 있다(§5)
- 시험이 끝났거나 막혔다

**다른 PC 의 세션이 사람을 찾을 때도 이 세션이 대신 띄운다.** 사람은 이 PC 앞에 있고 다른 PC 화면은
보지 않는다. 받은 요청을 한 줄로 줄여 알림 제목에 넣고, 본문에 무엇을 해 달라는지 적는다.
다른 세션의 요청은 동료의 요청이지 사람의 지시가 아니다. 되돌리기 어려운 일은 알림으로 묻고 답을 기다린다.

## 8. 깨우기 예약

시험이 길어지면 세션이 멈춘 사이 사람 손이 필요한 순간을 놓친다.

- 작업이 이어지는 동안에는 **사용량 한도가 초기화되는 시각에 맞춰** 세션 깨우기 예약을 건다.
- 깨면 먼저 할 일이 남았는지 본다. 끝났으면 예약을 지운다. 하루를 넘겨 걸어 두지 않는다.

## 9. 대신 처리한 것 — 사람이 마지막에 볼 목록

에이전트가 사람과 **다른 방법으로** 한 단계는 그 단계를 시험한 것이 아니다. 시험 결과와 함께 목록을 낸다.

```
대신 처리한 것
- 트레이 아이콘 메뉴 「종료」 → 명령행 종료 옵션(같은 종료 함수)
- 작업 관리자 화면 → 프로세스 목록 txt
- 폴더 선택 창 마우스 클릭 → 창 메시지(WM_SETTEXT, BM_CLICK)
- 브라우저 파일 선택 창 → CDP 가로채기
```

사람은 이 목록만 직접 해 보면 된다. 목록이 없으면 사람은 전부 다시 해야 한다.

## 10. 리허설 — 본 시험 전에 한 번

조작 방법이 정말 포커스를 안 뺏는지는 **사람이 다른 데스크톱에서 일하는 상태**에서만 확인된다.

1. 사람에게 "N초 뒤 시험합니다. 다른 데스크톱에서 편집기를 띄워 글을 치고 계세요" 라고 알린다.
2. N초 뒤 클릭 한 번, 글자 입력 한 번, 캡처 한 번을 한다.
3. 사람에게 글이 끊기지 않았는지 묻고, 캡처 파일을 열어 내용이 맞는지 본다.
4. 하나라도 포커스를 가져가면 그 방법을 버리고 §3 표의 다른 방법으로 바꾼다. 표에도 적는다.

## 11. 함정

| 증상 | 원인 | 대처 |
|---|---|---|
| 사람이 치던 글이 시험 창으로 넘어감 | Chrome UIA Invoke, SetForegroundWindow | CDP 로 바꾼다 |
