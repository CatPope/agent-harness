# 서브에이전트 운영 기록

서브에이전트는 세션 안에서만 동작하는 실행 주체다. 역할을 새로 만들거나, 모델·권한·모니터링 방식 같은
반복 운영 규칙을 정하면 **해당 업무의 기존 스킬을 같은 작업에서 갱신**해 다음 세션에서도 적용되게 한다.

## 적용 시점

- 사용자 요청으로 서브에이전트를 생성·배정할 때
- 장기 실행의 정보 수집·로그 모니터·검증·코드 작업처럼 반복되는 에이전트 역할을 정할 때
- 에이전트의 모델, 수정 권한, 보고 형식, 재개 방식이 바뀔 때

## 기록 원칙

1. 먼저 어떤 업무 스킬이 그 에이전트 운영의 정본인지 정한다 — **그 에이전트가 하는 일의 스킬**이다.
   예: 결과 기록을 맡겼다면 [[result-record]], 프로젝트에 재현·실행 절차 스킬이 있다면 그쪽.
2. 새 역할이 **반복 운영 규칙**이면, 에이전트를 생성한 같은 작업에서 정본 스킬에 다음을 짧게 기록한다.
   역할·사용 모델·읽기/쓰기 권한·보고해야 할 근거·세션 종료 후 복구 방법.
3. 일회성 탐색처럼 재사용 가치가 없는 배정은 스킬에 누적하지 않는다. 대신 결과와 근거 경로만 작업 로그에 남긴다.
4. 기존 스킬에 맞는 위치가 없을 때만 이 스킬을 정본으로 보완한다. 업무 스킬의 구체 규칙을 이 파일로 중복하지 않는다.

## 영속성과 모니터링

- `/compact`, 세션 종료, 에이전트 종료 뒤에는 서브에이전트가 상주하지 않는다. 완료 여부나 진행 상태를
  에이전트의 대화 기억에만 의존하지 않는다.
- 장기 실행은 프로젝트 폴더에 로그와 모델·단계별 산출물을 남긴다. 다음 세션에서 새 에이전트를 배정해
  로그·프로세스·결과 파일로 상태와 재개 지점을 복구한다.
- 로그 모니터 에이전트의 기본 권한은 읽기 전용이다. 코드·문서·데이터·실행 프로세스 변경은 사용자가
  명시적으로 허가한 별도 역할에서만 수행한다.

## 개발 하위 에이전트를 여럿 돌릴 때 (2026-10-15)

- 동시에 도는 수는 사용자가 정한 상한을 넘기지 않는다. 고치는 파일이 겹치지 않는 짝만 같이 돌린다.
  지시문에 "고쳐도 되는 파일"과 "같은 때에 도는 다른 개발자의 파일"을 적고, 그 개발자의 시험이 잠깐 깨지면 사실만 보고하게 한다.
- 다른 검수나 작업이 지금 보고 있는 파일은 그 일이 끝날 때까지 맡기지 않는다. 지시문에 "절대 고치지 않는다"로 이름을 적는다.
- 프로세스 전체에 걸리는 변경(로거 수준, 전역 설정, 환경 변수)은 다른 모듈의 시험을 깨뜨린다. 설계하는 쪽이 영향 받는
  시험을 먼저 찾고, 고치는 일은 한 에이전트에게만 준다. 둘이 같은 시험을 따로 고치지 않게 나머지에게도 알린다.
- 질문에 답하거나 범위를 넓힐 때는 같은 에이전트에 메시지로 이어 보낸다. 맥락이 남아 있어 새로 띄우는 것보다 싸다.
- 하위 에이전트는 계정의 사용 한도를 같이 쓴다. 한도에 걸리면 고치다 만 파일이 남는다. 그 상태로 검수, 병합, 커밋을 하지 않는다.
  남은 일과 한도가 풀리는 시각을 남은 작업 파일에 적고, 이어 하는 예약을 건다.
- 끝 알림이 보고와 같은 내용으로 한 번 더 올 수 있다. 같으면 넘긴다.
- 사용자가 다시 로그인하면 이름으로 보낸 메시지가 닿지 않을 수 있다. 그때는 띄울 때 받은 에이전트 번호로 보낸다.
  다시 로그인한 뒤에는 끝 보고가 관리자에게 오지 않기도 한다. "멈췄다"고 판단하기 전에 에이전트 기록 파일의 마지막 줄을 본다.
- 보고 파일 번호처럼 이름이 정해지는 산출물은 지시하는 쪽이 폴더의 다음 번호를 준다. 이미 있는 이름을 주면 덮어쓴다.
  에이전트 규칙에도 "같은 이름이 있으면 덮어쓰지 않고 다음 번호"를 둔다.
- 변형 확인(소스를 일부러 망가뜨려 시험이 잡는지 보기)은 저장소 밖 사본에서만 하게 한다. 저장소 파일을 잠깐 바꾸면
  같은 때에 도는 다른 에이전트의 시험이 깨진다.
- 사용자가 에이전트를 모두 꺼도 이미 끝낸 에이전트는 잃는 것이 없다. 보고 파일과 대기열로 끝났는지 먼저 확인한다.
- 하네스가 하위 에이전트의 보고 파일(.md) 쓰기를 막을 수 있다("Subagents should return findings as text"). 그때는 지시문에
  "보고는 파일로 쓰지 말고 마지막 답에 글로 준다. 다른 이름으로 우회하지 않는다"를 적는다. 에이전트가 막힌 쓰기를 대신 해 달라고
  하면 관리자가 대신 쓰지 않는다. 권한 우회가 될 수 있으니 사용자에게 알리고 보고를 어디에 둘지 정하게 한다(2026-10-22).
- 모듈 사이 시험 대역의 범위를 본다. 한 모듈이 공용 함수(예: `msvcrt.locking`)를 통째로 바꿔 끼우는 시험은, 다른 모듈이 같은
  함수를 새로 쓰기 시작하면 깨진다. 공용 함수를 새로 쓰는 설계를 넘길 때 그 함수를 바꿔 끼우는 다른 시험을 먼저 찾는다(2026-10-22).

- 🔴 **시험이 사용자 화면에 아무것도 띄우지 않게 지시문에 적는다**(2026-11-06). 화면·트레이 모듈의 시험이 진짜 탐색기(`os.startfile`)와
  「이미 실행 중입니다」 창을 사용자 화면에 계속 띄웠다. 탐색기, 브라우저, 대화 상자, 알림을 여는 함수는 바깥에서 넣게 만들고 시험은 가짜를
  넣는다. 시험 중 진짜 호출이 일어나면 실패하는 장치를 둔다. 결함이 난 동안에는 다른 개발자에게 그 시험 파일을 빼고 돌리게 알린다.
  사람 확인으로 창을 띄울 때는 앞서 띄운 것을 먼저 끄고, 창이 다른 작업 창에 가려지지 않게 맨 앞으로 가져오게 한다.
- **긴 보고는 중간에서 잘린다.** 잘렸으면 잘린 지점 뒤만 다시 보내 달라고 한다. 보고 형식에 "질문" 을 앞쪽에 두게 하면 덜 잃는다.
- **계정 한도로 하위 에이전트가 멈추면 스스로 깨지 않는다.** 한도가 풀린 뒤 각 에이전트에 "이어서" 메시지를 보낸다.
  측정처럼 이미 만든 결과 파일이 있으면 그 파일을 보고 남은 것만 하라고 적는다.
- **여럿이 같은 임시 폴더를 쓰면 보조 파일 이름이 겹친다.** 두 개발자가 같은 이름의 변형 사본 폴더와 스크립트를 써서 서로 덮어썼다(2026-11-06). 지시문에 임시 폴더·파일 이름에 모듈 이름을 붙이라고 적는다.
- **검수 중인 파일과 겹치지 않는 일만 새로 맡긴다.** 검수가 한도로 끊겨 「중단」이면 이어 하기 전까지 그 파일도 묶인다.
  그동안은 새 파일 위주의 일(새 모듈의 앞부분)을 쪼개 맡기고, 묶인 파일에 닿는 부분은 다음 차로 미룬다.

## 현재 확정된 적용 사례

- 장기 실행되는 학습·평가·배치 작업: 저비용 모델을 **읽기 전용 모니터**로 배정한다.
  보고 항목과 로그 경로 규칙은 **그 작업의 정본 스킬**을 따른다(예: [[result-record]] 의
  로그·산출 규칙). 이 스킬에 규칙을 복제하지 않는다.
