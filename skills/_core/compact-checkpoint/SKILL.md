# Compact 전 체크포인트

## 왜 있는가

compact은 이번 세션의 원문 맥락을 요약본으로 대체한다. **문서·스킬에 적어두지
않은 것은 요약을 거치며 흐려지거나 사라진다.** [[progress-log]]가 "새 정보가
들어오면 요청 없이 바로 갱신하라"는 원칙이라면, 이 스킬은 그 원칙이 **가장
크게 걸리는 순간**을 짚어준다 — compact 직전이다.

**"compact 진행할게요"는 요청이 아니라 예고다.** 예고를 듣고도 다음 응답에서
바로 반영하지 않으면, 사용자가 `/compact`를 실제로 실행한 뒤에는 이번 세션에서
있었던 논의의 결도 압축된 요약으로만 남는다. **예고를 받은 그 턴에 처리한다.**

**clear 는 더 급하다.** compact 은 요약이라도 남기지만 `/clear` 는 대화를 통째로 비운다.
문서·메모리에 없는 것은 하나도 남지 않는다. clear 예고도 같은 절차로 처리한다.

## 발동 시점

사용자 메시지에 compact 나 clear 예고가 있으면, **다른 요청이 함께 있어도 이것부터** 한다.
예고만 있고 다른 지시가 없어도 발동한다 — 확인을 기다리지 않는다.

명령 뒤의 복원은 이 스킬 몫이 아니다. 프로젝트에 SessionStart 훅(matcher `compact`, `clear`)이
있으면 그 훅이 남은 작업 파일에서 브리핑을 뽑는다. 이 스킬은 그 파일을 명령 전에 최신으로 만든다.

🔴 **복원 훅이 실제로 걸려 있는지 먼저 본다**(2026-10-21 사용자 요청). 프로젝트 `.claude/settings.json` 의
SessionStart(matcher `compact`·`clear`)를 확인한다. 없으면 사용자에게 알리고, 같은 사용자의 다른 프로젝트에 있는
훅(예: `compact_briefing.py`)을 본떠 그 프로젝트의 남은 작업 파일을 읽게 건다. 새로 건 훅은 지금 세션에 바로
적용되지 않을 수 있으니 다른 복원 경로(OMC 메모장 우선 영역, 메모리 색인 맨 위 줄)에도 재개 위치를 한 줄 남긴다.
훅·예약 작업에 **절대 경로를 박지 않는다.** 프로젝트 폴더를 옮기면 자동 메모리 폴더 이름도 바뀐다(경로의 영숫자 아닌
글자를 '-'로 바꾼 이름). 훅은 `CLAUDE_PROJECT_DIR`에서 계산하고, 폴더가 바뀐 세션에서는 예약 작업의 스크립트 경로부터 본다.
훅 파일이나 `.claude/settings.json` 쓰기가 권한 검사(자동 모드의 자기 수정 차단 등)에 막히면 돌아가지 않는다.
메모장 우선 영역과 메모리 색인 맨 위 줄에 재개 위치를 남기고, 훅이 없다는 것과 사용자 승인이 필요하다는 것을 알린다(2026-11-04).

## 🔴 일일보고 작업 정리 요청 (2026-10-28 사용자)

**"[일일보고 작업 정리 요청 — <날짜 또는 기간>]" 을 받으면 아래 절차 1~3 을 그대로 하고, 두 가지를 더한다.**

```

          그 프로젝트가 쓰는 곳)에 적는다. 일마다 시각(시작~끝, 또는 근거 시각)과 짧은 업무내용("ETL 오류 수정" 정도).
```

- 🔴 **반드시 답한다.** 답이 없으면 일일보고가 그 프로젝트 몫을 근거 없이 쓰게 된다
- 하던 다른 작업은 이어서 하지 않는다. 정리만 하고 끝낸다(백그라운드 실행이면 특히)
- 복원 훅 확인은 이 경우 하지 않는다(compact·clear 가 아니다). 3단계 스킬 갱신은 한다
- 요청 내용이 사용자 일정(회의·메일 업무)이면 그 세션의 회의·일정 기록에 같은 방식으로 적는다

## 절차

### 1. 이번 세션에서 반영되지 않은 것을 추린다

- 결정된 것 (사용자가 확정한 방향, 뒤집힌 계획)
- 정정된 것 (틀렸다고 밝혀진 이전 판단 — 내 것이든 남의 것이든)
- 새로 만들었거나 검증한 스킬/도구 — **세션 임시 폴더(작업별 tmp, scratchpad)에만 있는 도구는 영속 위치로 옮기고**
  메모리·문서에 적힌 경로를 고친다. 임시 폴더는 작업이 끝나면 지워진다. **예약 작업(세션 cron 프롬프트, Windows 작업 스케줄러 같은 OS 예약)이 그 경로를
  부르고 있으면 예약도 새 경로로 다시 건다** — 예약 문구는 압축 뒤에도 그대로 실행된다
- 아직 답을 못 받은 질문 (다음 세션이 이어받아야 할 것)
- **막혔던 것 · 기다린 것** — 무엇에 왜 얼마나 멈췄는지 **한 줄씩만**
- 🔴 **"남기겠다·기록하겠다" 고 말한 것이 실제로 반영됐나** — 약속은 대화에만 있다가 compact 에서 사라진다

⚠️ **마지막 항목은 기록만 하고 분석하지 않는다.** 압축 직전의 우선순위는 기록 보존이고,
병목은 여러 세션을 모아야 보인다. 여기 남긴 한 줄들이 나중에 [[bottleneck-review]] 의
재료가 된다. **압축 시점에 분석을 시작하지 마라** — 이 스킬이 *"다른 요청이 함께 있어도
이것부터"* 인 이유가 사라진다.

**이번 세션이 건드린 저장소·폴더를 전부 세어 본다.** 작업이 여러 곳에 걸쳐 있으면
한 프로젝트 문서만 보고는 빠진 것을 알 수 없다.

```bash
# 오늘 커밋이 있는 저장소를 훑는다
for r in <저장소들>; do git -C "$r" log --oneline --since="<오늘>"; done
```

⚠️ **커밋 로그가 남아 있어도 그것으로 대신하지 않는다.** 커밋에는 *무엇을 바꿨는지*가
남지만 **"왜 그렇게 갈랐는가"** 는 메시지마다 흩어져 복원되지 않는다. 그 판단이
진행 문서에 있어야 다음 세션이 이어받는다.

### 2. 작업 문서를 갱신한다 — [[progress-log]]

프로젝트가 메모리 폴더 방식(`settings.json` 의 `autoMemoryDirectory`)이면 바뀐 사실의 메모리
파일을 고치고 남은 작업 파일(예: `memory/project-next-tasks.md`)을 갱신한다. 그렇지 않고
프로젝트에 `프로젝트_진행상황_결정사항.md` 류의 진행 문서가 있으면 그 규칙대로
새 절을 추가한다. 없으면 그 프로젝트에 맞는 합당한 위치(README, 작업내역 등)에
남기되, **아무 데도 안 남기는 것보다는 스크래치 노트에라도 남기는 편이 낫다.**

승인은 필요 없다([[progress-log]]의 예외 규정과 동일 — 진행상황·작업내역·스킬
갱신은 사전 허가 없이 바로 기록한다).

### 3. 스킬을 갱신한다 — 🔴 빠뜨리지 않는다

🔴 **2026-10-14 사용자 지시: "clear/compact 할 때 skill 업데이트도 해주세요."** 문서만 갱신하고
끝내지 않는다. 이 단계는 선택이 아니다.

1. **이번 세션에서 쓴 스킬을 전부 적는다.** 만들거나 고친 스킬만이 아니라, 불러 쓴 스킬과
   그 스킬이 다루는 일을 한 경우(예: 보고서를 고쳤으면 report-writing·report-format)도 넣는다.
2. 스킬마다 이번 세션의 **사용자 피드백·정정·시행착오가 본문 규칙에 있는지** 본다.
   없으면 본문에 규칙으로 넣는다(이력에만 묻어 두면 다음에 안 읽힌다). 사람 이름·사내 표기는
   공유 스킬에 넣지 않고 일반화한다.
3. 이력 절에 사용 기록 한 줄을 남기고 업데이트 횟수·최근 업데이트 날짜를 고친다.
4. 넣을 것이 없는 스킬은 **"갱신 없음 — 이유"** 를 응답에 한 줄로 밝힌다. 말없이 건너뛰지 않는다.

같은 스킬 파일을 다른 세션이 같은 날 고쳤을 수 있다 — 고치기 전에 현재 내용을 다시 읽는다.

### 4. 증거를 붙여 응답한다

무엇을 어디에 반영했는지, 파일 경로와 함께 **간결하게** 알린다. 방금 쓴 내용을
다시 요약하지 않는다 — 어디에 뭘 추가했는지만 밝히면 된다. **스킬은 갱신한 것과
"갱신 없음" 인 것을 나눠 적고, 갱신한 스킬은 수정 시각과 바뀐 절을 붙인다.** 사용자는 그 다음
`/compact`·`/clear`를 진행하면 된다.

⚠️ 이 스킬은 **예고를 받아야** 돈다. 예고 없이 바로 `/clear` 를 치면 발동할 틈이 없다.

## 🔴 기록 저장 실패 신호 (2026-11-10)

Claude Code 가 **"the session transcript could not be updated"** 같은 문구를 보이면(예: `/rename` 결과) 그때부터 대화가 기록 파일에
안 남을 수 있다. 2026-11-06~11-09 에 계정 전환(`/login`) 뒤 이 문구가 나왔고, 세션 7개의 나흘치 대화가 통째로 사라졌다(Windows 이전 버전에도 없음).
이 신호를 보면 compact 예고를 기다리지 말고 **바로** 이 스킬의 1~3단계로 결정·남은 일을 메모리·문서에 적고, 사용자에게 알린다.
대화 기록에 기대지 않는 것이 이 스킬의 존재 이유와 같다.
`/compact` 가 **EBUSY(파일 사용 중)** 로 실패해도 같은 신호다. 11-12 원인 확정: 터미널 셸 프로필 스크립트가 세션 기록을 읽고 닫지 않아
잠갔다(PowerShell 에서 `[IO.File]::ReadLines` 를 foreach 로 돌다 break/return 하면 파일이 안 닫힌다). 계정 전환은 원인이 아니었다.
세션 기록(jsonl)을 읽는 도구는 반드시 공유 모드(FileShare ReadWrite)로 열고 바로 닫는다.

## 하지 않는 것

- 이번 세션 전체를 요약해서 보여주지 않는다 — 그건 compact 자체가 할 일이다
- 아직 결정 안 된 것을 임의로 결정해서 적지 않는다 — "확인 필요"로 남긴다
- 이미 문서화된 내용을 중복해서 다시 쓰지 않는다
