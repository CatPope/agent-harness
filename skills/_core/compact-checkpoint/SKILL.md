# Compact 전 체크포인트

## 왜 있는가

compact은 이번 세션의 원문 맥락을 요약본으로 대체한다. **문서·스킬에 적어두지
않은 것은 요약을 거치며 흐려지거나 사라진다.** [[progress-log]]가 "새 정보가
들어오면 요청 없이 바로 갱신하라"는 원칙이라면, 이 스킬은 그 원칙이 **가장
크게 걸리는 순간**을 짚어준다 — compact 직전이다.

**"compact 진행할게요"는 요청이 아니라 예고다.** 예고를 듣고도 다음 응답에서
바로 반영하지 않으면, 사용자가 `/compact`를 실제로 실행한 뒤에는 이번 세션에서
있었던 논의의 결도 압축된 요약으로만 남는다. **예고를 받은 그 턴에 처리한다.**

## 발동 시점

사용자 메시지에 compact 예고가 있으면, **다른 요청이 함께 있어도 이것부터** 한다.
예고만 있고 다른 지시가 없어도 발동한다 — 확인을 기다리지 않는다.

## 절차

### 1. 이번 세션에서 반영되지 않은 것을 추린다

- 결정된 것 (사용자가 확정한 방향, 뒤집힌 계획)
- 정정된 것 (틀렸다고 밝혀진 이전 판단 — 내 것이든 남의 것이든)
- 새로 만들었거나 검증한 스킬/도구
- 아직 답을 못 받은 질문 (다음 세션이 이어받아야 할 것)
- **막혔던 것 · 기다린 것** — 무엇에 왜 얼마나 멈췄는지 **한 줄씩만**
- 🔴 **"남기겠다·기록하겠다" 고 말한 것이 실제로 반영됐나** — 약속은 대화에만 있다가 compact 에서 사라진다

⚠️ **마지막 항목은 기록만 하고 분석하지 않는다.** 압축 직전의 우선순위는 기록 보존이고,
병목은 여러 세션을 모아야 보인다. 여기 남긴 한 줄들이 나중에 [[bottleneck-review]] 의
재료가 된다. **압축 시점에 분석을 시작하지 마라** — 이 스킬이 *"다른 요청이 함께 있어도
이것부터"* 인 이유가 사라진다.

**이번 세션이 건드린 저장소·폴더를 전부 세어 본다.** 작업이 여러 곳에 걸쳐 있으면
한 프로젝트 문서만 보고는 빠진 것을 알 수 없다.

```bash
# 오늘 커밋이 있는 저장소를 훑는다
for r in <저장소들>; do git -C "$r" log --oneline --since="<오늘>"; done
```

⚠️ **커밋 로그가 남아 있어도 그것으로 대신하지 않는다.** 커밋에는 *무엇을 바꿨는지*가
남지만 **"왜 그렇게 갈랐는가"** 는 메시지마다 흩어져 복원되지 않는다. 그 판단이
진행 문서에 있어야 다음 세션이 이어받는다.

### 2. 작업 문서를 갱신한다 — [[progress-log]]

프로젝트에 `프로젝트_진행상황_결정사항.md` 류의 진행 문서가 있으면 그 규칙대로
새 절을 추가한다. 없으면 그 프로젝트에 맞는 합당한 위치(README, 작업내역 등)에
남기되, **아무 데도 안 남기는 것보다는 스크래치 노트에라도 남기는 편이 낫다.**

승인은 필요 없다([[progress-log]]의 예외 규정과 동일 — 진행상황·작업내역·스킬
갱신은 사전 허가 없이 바로 기록한다).

### 3. 스킬을 갱신한다

이번 세션에서 만들었거나 고친 스킬이 있으면 **이력 절이 최신 사용을 반영하는지**
확인한다. 세션 중 있었던 시행착오(함정, 실패했던 접근, 정정된 판단)가 스킬 본문에
아직 없으면 지금 넣는다 — 다음 세션이 같은 시행착오를 반복하지 않게.

### 4. 증거를 붙여 응답한다

무엇을 어디에 반영했는지, 파일 경로와 함께 **간결하게** 알린다. 방금 쓴 내용을
다시 요약하지 않는다 — 어디에 뭘 추가했는지만 밝히면 된다. 사용자는 그 다음
`/compact`를 진행하면 된다.

## 하지 않는 것

- 이번 세션 전체를 요약해서 보여주지 않는다 — 그건 compact 자체가 할 일이다
- 아직 결정 안 된 것을 임의로 결정해서 적지 않는다 — "확인 필요"로 남긴다
- 이미 문서화된 내용을 중복해서 다시 쓰지 않는다

## 연계

- 실제 문서 갱신 규칙은 **[[progress-log]]**
- 검증되지 않은 주장을 적지 않도록 **[[work-review]]**의 "증거로 대조" 원칙을
  이 갱신에도 적용한다 — 방금 만든 스킬이나 도구를 "완료"라고 적기 전에
  실제로 동작 확인이 됐는지 스스로 되짚는다.
