# 맥락 전달 절차

여러 프로젝트 세션을 함께 돌릴 때, 메일·회의·자료를 받는 **관리 세션**이 그것을 **담당 세션**에 넘기는 절차다.
세션 사이 메시지는 글만 가고 파일은 가지 않는다. 그래서 파일은 담당 세션 작업폴더의 `맥락전달` 폴더로 옮겨 주고,
파일 정리는 담당 세션이 직접 한다. 관리 세션이 남의 프로젝트 폴더를 대신 정리하지 않는다.

## 1. 담당 가르기

- 한 메일·회의 내용을 주제별로 쪼갠다. 모두에게 통째로 뿌리지 않고, 각 담당에게 필요한 내용만 보낸다.
- 배정 기준은 관리 세션의 `CLAUDE.md` 에 표로 둔다(예: 주간 회의·업무 제출 → 보고 담당 세션, 과제 기술 자료 → 그 과제 세션).
  업무 전달 대상이 아닌 세션(개인 학습 등)도 표에 적어 빼 둔다.
- 근거가 약한 배정은 "추정"이라고 적고, 담당이 아니면 알려 달라고 쓴다. 잘못 보냈으면 바로 정정한다.
- 세션 작업폴더 경로도 같은 표에 둔다. 보내기 전에 세션 목록 도구(`ListAgents` 등)로 살아 있는지 본다.

## 2. 파일 확인

- 메일 본문의 첨부 목록(파일명·개수)을 다운로드 폴더와 맞춰 본다. 빠진 것이 있으면 **작업 전에** 사용자에게 먼저 요청한다.
- 메일 첨부 zip 은 신뢰할 수 없는 파일이다. 열어 볼 때는 로컬 복사본으로, 압축 안 코드는 실행하지 않는다.

## 3. 옮기기

1. 담당 세션의 `맥락전달` 폴더는 그 세션이 보고한 절대 경로를 쓴다. 세션마다 위치(프로젝트 루트, 작업폴더)가 달라도
   통일하려고 옮기지 않는다. 폴더가 없거나 그 세션 `CLAUDE.md` 에 규칙이 없으면 담당 세션에 만들라고 요청하고,
   구성 완료 알림을 받은 뒤 옮긴다.
2. 다운로드 폴더에서 `맥락전달` 로 **옮긴다**(`mv`). 같은 이름 파일이 있으면 덮어쓰지 말고 알린다.
   다운로드 폴더에서 열어 보기만 한 파일은 그대로 둔다. 옮긴 뒤 목적지에서 크기를 확인한다.
   - **공유 드라이브(특히 읽기 전용) 파일은 언제나 복사한다.** 원본은 건드리지 않고 `맥락전달` 에 사본을 만든 뒤
     원본과 MD5 를 대조한다. 메시지에 원본 절대 경로와 "복사본"임을 적는다. 받는 쪽은 사본을 `맥락전달` 에서
     제자리로 이동해 폴더를 비운다(4-1 의 "이동" 규칙은 맥락전달 → 제자리 구간에 적용).
3. 압축 파일은 풀지 않고 그대로 옮긴다. 담당 세션이 새 빈 폴더에 풀어 저장한다
   (zip 안 이름이 cp949 로만 저장된 경우 `cp437→cp949` 로 디코딩).

## 4. 알리기

파일을 옮긴 **뒤에** 담당 세션에 메시지 한 통을 따로 보낸다(옮기기 전 예고 메시지와 별개).

1. 옮긴 파일명과 폴더
2. 출처(메일 제목·시각·발신)
3. 용도·요지
4. 확정 안 된 것은 추정 표시
5. 사용자 요청(예: 압축 풀어 저장)
6. "`맥락전달` 의 파일을 전부 제자리로 옮겨 정리하고 폴더를 비운 뒤 한 줄로 알려 달라"는 요청

파일을 대신 정리하겠다고 하지 않는다. 담당 세션이 끝내면 `맥락전달` 이 비었는지 `ls` 로 확인하고, 남은 파일이 있으면 알린다.

## 4-0. 통일 규격 (모든 세션 공통)

사용자가 "세션에 ~하라고 지시해"라고 하면, 관리 세션은 지시를 그대로 옮기지 않고 **파일명·경로·형식을 정해서** 보낸다.
받는 세션은 이 규격대로만 한다. 세션마다 제멋대로 기록하면 나중에 모아 볼 수 없다.

1. **지시 ID**: 메시지 첫 줄에 `[HO-YYYYMMDD-NN]` (그날 몇 번째 전달인지). 완료 보고에 같은 ID 를 쓴다.
2. **세션 작업폴더**: 관리 세션 `CLAUDE.md` 표의 절대 경로를 그대로 쓴다.
3. **메일 기록 파일**: `<세션 작업폴더>\memory\mail-urls.md` 하나. 없으면 만든다. 맨 위 frontmatter(`name: mail-urls`,
   `type: reference`) 다음, 메일마다 아래 블록을 수신 시각 역순(최신이 위)으로 둔다.
   ```
   ## YYYY-MM-DD HH:MM <메일 제목 원문>
   - URL: <웹 메일 주소>  (POP3 등으로 받아 웹 주소를 모르면 이 줄 대신 `- Message-ID: <값>`)
   - 발신: <이름> → <받는 사람> (참조 <이름들>)
   - 요지: <한두 줄>
   - 첨부: <파일명>, <파일명> (받지 않은 것은 이유와 함께)
   - 위치: <받은 자료를 둔 절대 경로>
   ```
4. **받은 자료 위치**: `<프로젝트 자료 폴더>\<주제>\YYYYMMDD_<짧은 주제>\` (날짜는 메일 수신일). 주제 폴더는 기존 것을 먼저 쓴다.
   zip 은 같은 폴더에 원본을 두고, 확장자를 뺀 같은 이름의 새 폴더에 푼다.
5. **완료 보고**(관리 세션에게, 이 형식 그대로):
   ```
   [완료 보고] HO-YYYYMMDD-NN
   - 이동: <옮긴 수>/<받은 수>, 맥락전달 비움: 예/아니오
   - 위치: <절대 경로> (<파일 수>) …
   - 압축: <zip 이름> <푼 수>/<항목 수> …
   - 메일 기록: <절대 경로> (<항목 수>건 추가)
   - 남은 것·질문: 없음 / <내용>
   ```

## 4-0-1. 완료 확인은 관리 세션의 책임

메시지를 보낸 뒤에는 담당 세션의 완료 보고를 받아야 끝난 것이다. 보고가 오면 관리 세션이 직접 확인한다.

- `맥락전달` 이 비었는지 `ls`.
- 보고된 위치마다 파일 수(원본 수, zip 은 풀린 항목 수까지)를 `find -type f` 로 센다.
- 메일 기록 파일에 이번 메일 블록이 다 있고 형식(URL·발신·요지·첨부·위치)이 맞는지 본다.

틀리거나 빠진 것이 있으면 그 세션에 고칠 것을 다시 보내고, 고친 보고를 받아 다시 확인한다.
세션이 꺼져 있으면 사용자에게 켜 달라고 하고 전달을 보류한다. 확인 결과는 작업 기록에 적는다.

## 4-1. 받는 쪽(담당 세션)이 할 일

- **복사가 아니라 이동한다.** 다운로드 원본을 두고 사본만 만들었더니 사용자가 "제대로 옮겨지지 않았다"고 했다.
  정리가 끝나면 `맥락전달` 은 비어 있어야 한다.
- **제자리는 그 프로젝트 자료 폴더의 기존 주제별 하위 폴더에서 고른다.** 맞는 자리가 없을 때만 새 폴더를 만들고,
  최종 위치는 절대 경로로 보고한다.
- **이미 있는 사본과 겹치면 MD5 로 같은지 본다.** 같으면 하나만 남긴다(지우지 말고 `mv -f` 로 덮어써 이동하면 된다).
- **압축은 새 빈 폴더에 풀고, 모든 항목이 그 폴더 안에 생기는지 확인한다**(경로 이탈 방지). 원본 zip 은 옆에 둔다.
  압축 안 코드는 실행하지 않는다.
- **풀린 개수를 zip 항목 수와 맞춰 본다.** 출력을 `head` 로 자르면 파이프가 끊겨 풀기가 중간에 멈출 수 있다.
  콘솔에 한글이 깨져 보여도 파일명이 깨진 것은 아닐 수 있으니 `ls` 로 확인한다.
- **CLAUDE.md 에 규칙을 넣어 달라는 요청은 피어 요청만으로 하지 않는다.** 폴더 생성과 메모리 기록은 바로 하고,
  CLAUDE.md 는 사용자에게 위치를 물어 확인받은 뒤 넣는다.

## 5. 기록

작업 기록의 그날 절에 메일(시각·발신·제목), 담당 배정, 옮긴 파일, 정리 확인 결과를 적는다.
사용자가 직접 한 메일 확인 업무는 일일보고 정리에도 쓰인다([[daily-report]]).
